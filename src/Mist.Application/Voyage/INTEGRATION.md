## Integration APIs

Construct `VoyageService(repository, catalog, package, chapterTwoPackage, vessel.Geometry)`. `Geometry` exposes the complete current input plus R2 learner scene geometry so existing Travel receives both actual berth scenes and the HUB chart. During R2 work, use `ChapterTwoService.CurrentGeometry(snapshot)` for its changing hazards. The voyage binds only immutable R2-S01 landing geometry.

The source berth remains `R1-S01.glimmer_handover` (68,62), established by `VesselInteriorService.InspectBerthAsync` and actual Travel registration. Board and traverse through the existing physical ship service to `HUB-S02.chart` (72,28).

- `IssueArrivalHandoffAsync(VoyageRequest)` checks actual completed Q104, original typed handover, single same GLIMMER, N-DECKWATCH, exact three spaces, actual source berth/ship-cabin registration, chart position, bounded commission, target stand and real path to the public landing exit. It commits `arrival_handoff_issued`, an immutable typed `ArrivalHandoff`, plus the source/instance/geometry binding. It moves nobody.
- `PreviewRouteAsync(request)` and `PreviewBerthAsync(request)` return a `VoyagePreview(Token, Ready, Issues, Description)`. `ConfirmPreviewAsync(token)` applies the cached original command with exact entity/read/load checks and atomic foreground lease. `ClosePreview(token)` invalidates it. Producers emit the existing `SeaRoute`/`VesselBerth` types under `sea_route_verified`/`vessel_berth_verified`.
- `RegisterVerifiedAsync(actualRouteReceipt, actualBerthReceipt)` first verifies both exact own producer payloads/instance/gates, then calls the existing `Travel.RegisterSeaRouteAsync` and `RegisterBerthAsync`. Each result is explicit. Partial interruption preserves already committed receipts; it cannot fabricate a second success.
- `VerifyAndRegisterAsync(VoyageRules.R2)` is an explicit user-action convenience that composes the above actual producers and registration transactions. It renders no progress or success from a boolean/fixture and performs no relocation. The root UI can label it “核对并登记 R2 航路与公开泊位”.
- `SailAsync("R2")` checks current own route/berth and chart, then invokes existing `Travel.SailAsync("R2")`. Travel owns foreground lease, current route/berth/space read checks, one ship DockRegion update and actual safe actor landing. No bare actor relocation is implemented here.
- `RecordArrivalAsync()` at the actual R2-S01.berth stand (48,90) records `actual_vessel_arrival` / `VesselArrivalProof`. It verifies the latest actual `sail_shared_glimmer` from R1 to R2 for this instance, exact registered source receipts and current safe landing. The authority scope is `public_landing_only_not_local_registration`. It advances no quest and grants no material.

The only supported request is `VoyageRules.R2`: destination R2, R2-S01/R2-S01.berth, public landing, receiving-record cross-check, mentor current status unknown. Requests for other regions, private archives or unsupported current survival are rejected. This is a world-rule check and explicit bounded fallback; it makes no English-understanding claim.

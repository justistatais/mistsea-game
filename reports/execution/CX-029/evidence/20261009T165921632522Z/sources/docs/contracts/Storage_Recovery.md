# 存档与恢复

profile.sqlite 是当前默认世界库，control.sqlite 保存删除墓碑、外发许可版本、备份注册和恢复指针。两者都必须保留。冒险检查点只复制世界分支，不恢复学习观察或删除世代。6 个手动槽、5 个滚动槽、命名保护点使用不同槽键。

BackupAsync 使用 SQLite BackupDatabase API。备份通过完整性、外键、profile_id、schema、release 和序号检查后登记哈希。恢复写入新候选，重放删除墓碑，最后切换控制库指针；原数据库和一致备份都保留。实际主库已损坏时，可在确认的备份 ID 下使用 ProfileStore 的 recoveryBackupId 入口，避免先打开损坏主库。未登记、被修改或不兼容的备份拒绝恢复。

控制库缺失不能自动按世代零重建。保留损坏原件及主库，恢复原控制库后再使用登记备份；无法找回控制库时需要明确的隔离恢复方案，不能声称删除记录已恢复安全。

迁移只对一致候选执行；失败不会覆盖当前库。当前 schema 1 尚无跨版本生产迁移，不伪称支持未知旧格式。受管理备份清理检查根目录边界、实际路径和 reparse point，不遍历或删除用户外部文件。

战斗重试只恢复遭遇入口范围、实际尝试消耗和尝试编号。已结算遭遇不能通过重试返还消耗；草稿、材料和先前已交付运输保持。继续、切换阶段和加载令牌不提供新补给。

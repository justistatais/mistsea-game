# 第一部分：游戏总体规格与设计原则

文档：`Game_Design_Core.md`  
版本：`v0.1`  
日期：2026-10-08  
适用项目：《雾海档案：第七座灯塔》（暂定名）  
用途：作为后续第 2—12 部分的共同设计基线；不是完整程序规格，也不是立即实现全部游戏的开发指令。

## 文档效力

本文采用三种状态：**基线规则**是后续设计不得默默绕开的要求；**待验证初值**是供原型测试的数字，可以调整；**后续定案**是明确交由其他部分解决的细节。未特别标注的规则，均作为本版基线。

本版是提出供项目采用的第一份详细规格，不表示用户已经逐条批准，也不表示数值或学习效果已经验证。后续发现冲突时，应修改版本并记录影响，不能让不同文档各自保留一套相反规则。

此前提出的游戏名称、六区域世界结构、角色姓名和具体技能均仍是候选方案；本部分主要冻结体验与系统边界，不提前冻结第二部分的剧情。

# 1. 产品定位与范围（CORE-01）

## 1.1 一句话定义

**一款以原创剧情和角色成长驱动、以英语信息理解与书面表达解决问题的单人冒险 RPG。**

玩家的直接目标是探索、调查、战斗、救援和作出决定；产品的长期目标是让玩家持续练习阅读、听力、写作及其支撑知识。

英语不能只是装饰，也不能成为每次操作前必须缴纳的“答题费用”。判断某个任务是否成立，采用两个检查：把材料翻译为中文后，任务仍有冒险或推理价值；删去关键信息理解后，玩家不能仍然无条件依靠任务箭头完成全部决策。

## 1.2 产品规格

| 项目 | 本版决定 |
|---|---|
| 首发目标 | Windows PC 单机；其他平台不进入首个可玩版本的验收范围 |
| 输入 | 键盘与鼠标；不要求麦克风，不要求快速打字或精确反应 |
| 视觉形态 | 区域节点地图＋可探索的 2D 场景＋人物立绘＋轻量战斗表现 |
| 地图性质 | 分区域、可重访、受剧情与能力控制开放；不是连续开放世界 |
| 核心玩法 | 探索、信息调查、解谜、书面沟通；战斗和成长提供风险、选择与回报 |
| 战斗方向 | 可暂停的信息查看＋回合制决策；详细规则由第 8 部分制定 |
| 语言呈现 | 英语承载剧情材料，中文承担可选辅助与默认系统说明 |
| 联网依赖 | 主线可离线完成；联网 AI 属于可选增强，不是启动或推进条件 |
| 玩家账户 | 首版不强制注册；使用本地玩家档案与独立冒险存档 |
| 内容结构 | 有确定主线、有限分支、可扩展支线；不把无约束实时生成当作主线引擎 |

本版不做多人、PvP、语音评分、大规模 3D 建模、开放世界生存模拟、复杂经营模拟或永久死亡模式。它们不是后续“顺便加入”的功能，新增必须重新评估范围。

探索和战斗必须有实际空间、物件与状态变化，不能最终缩水成“在菜单里看文字、答题、领取装备”。美术可以简化，核心交互不能消失。

# 2. 目标玩家与学习目标（CORE-02）

## 2.1 服务谁

主要服务有一定英语基础、愿意阅读中长材料、希望提升读听写能力的中文使用者。内容与交互先按大学生及成年自主学习者设计，不以零基础儿童启蒙为目标。

以中高阶英语基础作为主要设计起点，但不要求输入雅思成绩，也不以一个总分决定能否进入。阅读较强、听力较弱或写作较弱的玩家，应得到分技能支持，而不是被统一归为“低等级”。

较弱的玩家可以使用辅助路径体验，但本项目不承诺从字母、基础发音和初级语法完整教起；高水平玩家也不能被迫重复大量已经掌握的基础内容。

## 2.2 “雅思 6.5 及以上”的操作定义

IELTS 与 CEFR 没有精确的一一对应关系；官方指出 C1 的最低边界大致落在 IELTS 6.5 与 7 之间，该对应讨论也不能被直接当成每个单项的精确换算。[S1]

因此，本项目将**较高 B2 至 C1 范围的语言需求**作为材料与任务设计参照，序章减少信息负担和操作复杂度，不自动降成初级英语。最终难度由材料、任务要求、支持条件和玩家实际表现共同校准，不以文章长度或生词数量单独判定。

IELTS 总分由听、说、读、写四项成绩共同计算；本游戏不训练口语，因此不显示或承诺“通关获得雅思总分 6.5/7”。[S2]

产品目标写为：**帮助玩家在陌生材料中更独立地完成中高阶阅读、听力与写作任务；具体提升幅度需要验证。**

## 2.3 能力范围

| 能力 | 游戏必须提供的机会 | 不应冒充的证据 |
|---|---|---|
| 阅读 | 定位信息、理解指代与限定、辨认立场、整合多份材料、理解完整论证 | 打开过文档，不等于读懂 |
| 听力 | 辨认关键信息、更正、态度、多说话者关系，处理较长语段 | 看字幕答对，不等于独立听懂 |
| 写作 | 从短消息到说明、摘要、比较与论证，并进行修改 | 选择预制句，不等于独立写作 |
| 词汇 | 多义、搭配、词族、语域与跨情境使用 | 认识书面词形，不等于能听出或使用 |
| 语法与语篇 | 理解句法关系、组织段落、控制时态与逻辑、表达确定性和保留态度 | 只做语法选择题，不等于能准确表达 |
| 拼写与编辑 | 拼写、标点、句界、修改歧义与不恰当表达 | 系统自动纠错后的成品，不等于自主产出 |

“除了口语以外的所有英语”在产品上解释为覆盖以上主要能力，不承诺穷尽所有行业术语、文学传统和专业知识。

阅读不能长期只剩便条。IELTS 学术阅读包含多种文体及详细逻辑论证，材料面向非专业读者；本项目据此保留完整的较长材料，并给虚构技术名词提供定义，不靠世界观黑话制造难度。[S3]

听力不能只是把已经显示的文字朗读一遍。IELTS 听力涉及日常社会与教育训练等场景，并使用不同英语口音；本项目据此要求声音具有独立的信息价值，同时保留无障碍文本路径。[S4]

写作不仅练正确句子，还要练任务回应、组织、词汇和语法控制。IELTS 写作的四个评价维度可以作为设计参考，但游戏内评价不是官方评分。学术写作专项中的 150/250 词要求也不应变成每封游戏留言的最低字数。[S5]

## 2.4 起始诊断与最终检验

首次进入时，提供可跳过的短诊断，用于推荐支持设置；它不授予角色属性，也不决定主线入口。跳过时使用默认支持，之后逐步收集信息。

终局呈现剧情结果与分技能学习记录，不生成未经校准的雅思预测分。后续学习效果检验必须使用未见过的材料，并包含脱离本游戏设定的主题；熟悉剧情、记住答案和完成度都不能单独证明迁移。

# 3. 核心体验与游玩节奏（CORE-03）

## 3.1 核心循环

**收到目标 → 探索 → 获取材料 → 比较信息并形成判断 → 操作、交涉或战斗 → 执行书面方案 → 看到结果 → 获得成长与新问题。**

这是完整任务链，不要求每个房间都包含全部环节。普通支线可以侧重其中两三项，休息和角色交流场景也不必强行挂学习测验。

每个核心主线任务至少包含一次依据信息作出的实质决策。每个完整常规章节必须给出阅读、听力和真实书面产出的机会；不能把写作留到最终章才出现。序章也应让玩家接触三者，只缩小任务规模。

玩家始终应能回答三个问题：我现在要解决什么？我已经确认了什么？我接下来可以调查或尝试什么？任务界面显示目标与已知事实，不直接替玩家计算最终答案。

## 3.2 时间尺度：待验证初值

| 层级 | 初始目标 | 应当获得的进展 |
|---|---:|---|
| 最短可用游玩 | 10—15 分钟 | 找到线索、完成局部机关或保存一份有进展的草稿 |
| 常规一次游玩 | 30—45 分钟 | 完成一个有结果的小段落，而非必须完成整条主线任务 |
| 主要任务链 | 45—90 分钟，可拆分 | 形成一次完整调查、行动与后果闭环 |
| 完整主线 | 45—60 小时 | 完成主要区域与终局 |
| 较充分体验 | 80—120 小时 | 包含支线、同伴内容和复盘等 |

以上是游戏时长的设计预算，不是学习达标所需时间或开发工期。主线预算应计入正常阅读、重听和写作，不靠忽略这些时间让数字好看；实际时长通过样章测量后修订。

普通任务避免连续安排两段长写作。长篇报告必须可以拆开完成，也不能在未经提示的情况下紧接首领战强制开启。

战斗有效时长在典型主线任务中先按不高于约 20% 的目标测试；少数战斗主题任务可例外。观察玩家是否因战斗重复而中断调查，比机械追求比例重要。

## 3.3 一次常规游玩的体验样例

玩家回到港口，先看到未完成目标和自己上次固定的证据；随后调查工坊，听到修订后的调度消息，发现旧记录不再成立。

他选择潜入或战斗取得零件，修复装置，再开始给负责人写行动说明。时间不足时保存退出；下次回到原草稿，而不是重新寻找全部材料。

任务结算先展示船只是否成功撤离、人物如何反应和所得装备，再提供可展开的学习反馈。没有必须点完几十张错题卡才能离开的结算墙。

# 4. 信息、谜题与任务的公平性（CORE-04）

## 4.1 四类信息必须分开

**世界事实、人物说法、玩家假设、系统提示**不是同一件事。

角色说“支架没有问题”不等于世界事实就是如此。证据板必须保留出处；玩家可以做错误标注，但系统不能把该标注当成已经证实的任务状态。

信息面板还必须区分“没有找到支持材料”和“已被材料否定”。未知不能默认为错误，人物犹豫也不能直接被标为说谎。

## 4.2 关键线索必须可获得

关键线索可以被机关、剧情前置或调查步骤保护，但必须有可行路径。不能只允许某一种加点、某位可永久错过的同伴或某件随机掉落装备获取唯一主线证据。

发现率、隐藏物品和属性可以影响额外奖励、捷径与准备程度；必需信息的取得路径不能靠随机运气决定。

重要证据不得在任务结束前因误出售、场景重置或一次错误点击永久丢失。剧情确实销毁原物时，必须保留已读记录或提供明确的替代取证路径。

## 4.3 解谜不能靠猜作者意图

唯一解谜题必须有充分材料，并能指出哪些事实支持解法。开放决策必须允许多种满足约束的方案。

任务可以有不确定性，但应让玩家知道信息可能不足。不能先让玩家按完整信息推理，事后凭空新增隐藏事实来证明其“英语答错”。

## 4.4 防止无意义的信息绕过

任务箭头可以指向调查地点，不能直接写出本该由材料推出的路线。与关键语言毫无关系的颜色、物品编号或按钮位置，也不能稳定泄漏唯一答案。

选择正确按钮可以推进世界，但单次选择不自动证明理解。学习判定还需看任务证据和支持条件，必要时在之后的不同情境中再验证。

# 5. 游戏进度与学习进度（CORE-05）

## 5.1 三种结果分别保存

| 结果 | 记录内容 | 不允许的混用 |
|---|---|---|
| 冒险结果 | 任务、路线、设施、人物和阵营状态 | 不能根据未经确认的语言评分决定人物命运 |
| RPG 成长 | 等级、属性、技能、装备与资源 | 不能把角色等级显示成英语等级 |
| 学习证据 | 某项能力在什么材料、条件和帮助下出现了何种表现 | 不能因为通关就标成全部掌握 |

界面先给玩家看任务结果，学习记录在独立位置查看。词汇、阅读、听力和写作不合并为一个含义不清的“英语战斗力”。

## 5.2 学习状态的最低要求

至少能区分“接触过”“借助帮助完成”“在本次条件下独立完成”“在新情境中再次验证”与“尚未评估”。这些是证据状态，不是一次成功就永久升级的固定阶梯。

帮助的影响要按目标细分。查一个无关生词，不应抹掉整个任务的听力表现；查看了目标录音全文，则不能把该次后续答案当成纯听觉理解的证据。

有助于理解的反复练习可以记录，但看过答案后的同题成功，不能冒充陌生材料的首次独立完成。

## 5.3 通关与学习覆盖的关系

主线正常路径必须持续包含读、听、写任务，不能让某个职业永久绕过一个技能。

玩家使用模板、译文或完整提示后仍能继续剧情，任务奖励不因辅助设置自动缩水。相应能力保留真实记录，未得到的独立证据以后用新的内容验证。

**剧情可以先完成；学习记录可以仍有待验证项目。** 不把这些项目变成限制下一章、扣除装备或强制每日补交的作业债务。

# 6. 三条独立难度轴（CORE-06）

| 难度轴 | 可调整内容 | 不得连带改变 |
|---|---|---|
| 战斗难度 | 敌方伤害、资源余量、容错和重试压力 | 不改变文章、英语评价或谜题事实 |
| 解谜支持 | 目标提示、线索定位、推理提示、完整解法入口 | 不自动给语言能力加分或减分 |
| 语言支持 | 词义、句法解释、重听、分段播放、字幕与翻译 | 不修改世界事实、结局条件或装备价值 |

首次设置只给少量预设，默认“标准战斗＋按需谜题提示＋英语原文和可调用中文辅助”。之后可以分别调整，不要求重开存档，也不绑定惩罚性成就。

低辅助预设减少默认提示，不提高怪物伤害，也不把英文替换为大量冷僻词。高辅助预设增加解释和分步组织，不把整条主线改造成初级题库。

自适应优先调整下一次练习材料与支持建议。当前已经进入的任务保持材料、音频、机关条件和答案版本一致，不能因为玩家表现变化而中途改写证据。

正式测评练习与冒险模式分开。测评可按明确规则限制工具和播放次数，但必须提前说明；使用帮助后改变本次证据标签，而不是取消游戏存档。

# 7. 中文、翻译、提示与复习（CORE-07）

## 7.1 默认语言政策

系统菜单、操作教程和错误说明默认中文；剧情文本、任务文献和人物对话默认英文。名称初见可双语展示。

任务概要可以中文概述目标，但不能把关键条件、正确路线和谜底全部提前翻译进目标栏。世界观专名可以免费释义，不能靠不解释自造词来卡住玩家。

关键音频默认可重播和暂停，字幕随时可打开；在玩家已选择字幕或无障碍设置时，优先遵守其设置，不强制隐藏。

中文翻译、字幕、字典和基础提示不消耗金币、体力或付费道具。借助文本的听力任务仍可完成冒险，但记录输入方式发生了变化。

## 7.2 两条提示链

**语言提示：词义 → 句法或语篇关系 → 分句解释 → 全文翻译。**

**解谜提示：目标提醒 → 应比较哪些材料 → 推理关系 → 可执行的完整解法。**

查词默认只解释词，不直接跳到谜底；索要完整解法时，系统应明确说明会揭示方案。玩家可以直接选择所需层级，不必先故意失败几次。

查看提示本身不触发任务行动。知道某个解法后，仍由玩家选择是否执行。

## 7.3 复习规则

复习可以通过来信、旧案、新委托和营地练习出现，但不得强行改变固定主线事实。

安排同一语言点在不同情境中再次出现，优先要求理解与使用，而不是只展示“今日已复习”。具体间隔、模型和掌握阈值由第五部分制定，本部分不伪装成已有验证的算法。

玩家长时间未游玩后回来，不损失角色属性、不扣装备，也不被强制拦在大量补做任务前。系统提供简短恢复摘要和可选复盘。

# 8. 写作的强制边界与判定规则（CORE-08）

## 8.1 默认必须存在真实产出

正常主线中的沟通任务以自由输入为默认，不能统一退化为句子拼接或选择答案。空白文本不能被系统标为“写作完成”。

任务写作依据沟通目的规定必要内容，不以字数越多越好。短留言、任务说明与长报告属于不同负担，不统一使用作文标准。

普通写作不倒计时，不要求一次完成。材料可边看边写，草稿可跨会话保留；独立限时写作只存在于明确选择的专项测评。

## 8.2 不能把语言不完美等同于行动失败

判断拆成三层：**玩家打算做什么、方案是否满足世界约束、文字表达得怎么样。**

例如，玩家的方案路线正确但冠词有误，负责人可以执行，语法问题留在反馈中。若否定词使指令含义相反，系统先确认意图，让玩家修改或明确选择，不直接施加灾难后果。

不同合理表达应被接受。系统不确定时必须保留“无法可靠判断”的状态，不能给出伪造的精确分数。

## 8.3 帮助与暂时跳过

提供提纲、句式框架和示例分析。仍无法完成时，允许玩家选择“辅助整理并确认行动”，由系统给出受控草稿或结构化确认，并明确记录本次使用了写作帮助。

这是兜底路径，不是默认按钮替代所有写作。玩家仍需确认关键行动，系统不会自动替其作出剧情立场选择；辅助完成不冒充自主写作证据。

长篇写作可以先存草稿，转去做不依赖该通信结果的活动。确实依赖该说明的后续步骤，只在有效提交或显式辅助完成后开放。

## 8.4 离线时的诚实降级

离线时，保留自由写作与草稿。必要行动通过结构化信息确认和固定世界规则判定；此时不能谎称系统已经理解并评价了全部自由文本。

任务可以显示“行动方案已确认，写作尚未评估”。只有用户选择使用可用的评价服务时，才提交相应文本；不用联网也能继续主线。

联网评价可以辅助提取意思和提供反馈，但重大行动仍展示解释结果让玩家确认。语言模型输出本身不直接改写世界状态。

## 8.5 反馈节奏

先反馈影响意思的问题，再反馈组织，最后选择少量词汇与语法问题。重要修改给玩家重新表达的机会，不默认全文代写并自动记为已掌握。

不要求玩家在一次任务后处理所有语言问题才能离开。完整记录可保留，当前只突出最有价值的下一步。

# 9. 失败、暂停、存档与回档（CORE-09）

## 9.1 四类失败分别处理

| 类型 | 默认处理 | 禁止处理 |
|---|---|---|
| 战斗失败 | 回到战前检查点，恢复该检查点资源，允许调整策略 | 重做已完成的阅读与写作 |
| 谜题误操作 | 展示可解释反馈，可撤销或复位相关装置 | 随机销毁唯一线索形成死档 |
| 理解或表达不足 | 提供反馈、澄清与支持，允许再次尝试 | 把一个语言错误直接换算为永久人物死亡 |
| 玩家确认的剧情选择 | 执行预先设计的世界后果 | 事后凭语言评分改变玩家立场 |

部分谜题可以有局部资源或战术代价，但资源耗尽后必须仍有恢复或替代路径。错误需要有信息价值，不能只扣血却不说明发生了什么。

读文献、写作、查词和普通听力交互期间不推进会造成惩罚的现实时间。剧情可以说“风暴将至”，默认通过明确行动步骤推进局势，而不是让玩家因为阅读慢而失去结局。

## 9.2 存档要求

提供手动存档、滚动自动存档和重要选择前的保留点；不只允许在营地保存。任意正常交互阶段可暂停。

退出后至少恢复到最近完成的稳定行动边界。写作草稿、已收集文献、笔记和音频位置独立保存，不因战斗重试消失。战斗恢复边界及具体槽位数由第十二部分细化，但不能出现资源扣除与行动执行只保存了一半的情况。

正常退出必须保存最后草稿。异常中断下，草稿丢失量以不超过约 5 秒编辑内容作为首版待验证目标；这不是对所有硬件故障的保证。

## 9.3 回档与学习历史

冒险存档可以回到过去；同一玩家的学习档案保留已经接触材料与使用帮助的历史。看过答案再回档成功，不被重算为首次陌生任务的独立表现。

学习历史不能把另一条剧情路线的线索自动灌入当前角色的证据板。多名玩家使用不同档案，数据不混合。用户可以主动删除或重置学习数据；删除后显示证据缺失，不重建虚假的既往成绩。

## 9.4 必须覆盖的边界情况

| 情况 | 基线处理 |
|---|---|
| 提前拿到任务物品 | 接任务时识别已有物品，不要求重新拾取 |
| 关键物品遗失风险 | 阻止误丢弃，或提供明确恢复机制 |
| 必需 NPC 因剧情不在场 | 提供预设替代取证或沟通路径，不临时生成矛盾 NPC |
| 玩家离开再回来 | 保存机关、拾取、对话与草稿状态 |
| 重复提交任务 | 不重复奖励，不重复应用同一剧情后果 |
| 音频缺失或播放失败 | 提供文本路径并标记实际输入方式，不假报听力完成 |
| AI 服务失败 | 使用离线规则与未评估状态，不阻断主线 |
| 内容更新与进行中任务不一致 | 保留原版本或明确迁移，不静默改掉当前谜底 |

# 10. 自由度、成长与奖励（CORE-10）

## 10.1 自由度的范围

宏观主线采用有顺序的章节骨架，区域内部允许在满足依赖的前提下自由调查。支线与同伴任务提供不同顺序和局部后果，不要求每次选择都产生一套完整独立地图。

允许玩家选择进入路线、调查顺序、队伍、技能构筑、资源安排和符合事实的解决方案。不承诺任意杀死所有 NPC、任意毁坏关键设施或在自由输入中凭空创造世界事实。

重要不可逆选择提示影响范围并留下保留点，但不必提前剧透全部后果。结局取决于实际行动、证据、关系与设施状态，不取决于英语分数或玩家观点是否符合某个标准答案。

## 10.2 RPG 成长应改变方法

属性、技能和装备用于提供新的战斗组合、探索路径与资源取舍。高感知可以发现额外痕迹，但不能直接翻译全部英文；高力量可以开侧门，但不能永久绕开主线的学习机会。

角色成长不能只剩数值加成，也不能把“使用十个高级单词”换算成十倍攻击力。具体等级、属性数量、阶位、职业与技能公式由第七部分制定。

## 10.3 奖励政策

主线经验与关键装备按冒险目标结算，而不是按答对题数发放。相同世界结果，不因翻译、字幕或提示设置自动减少基本奖励。

可选高难度内容可以给收藏、额外故事和一般奖励，但不能垄断通关必需的力量。重复同一道练习不得成为最高效的刷经验路线。

战斗和生活补给可以消耗游戏资源；词典、字幕、提示和基本语言反馈不加入金币经济。首版不做体力限制、每日强制打卡或连续登录损失机制。

# 11. AI 权限、内容确定性与联网（CORE-11）

## 11.1 大量事件是内容方向，不是放弃约束

保留大量主线外事件、支线、文献和同伴互动的扩展空间，允许 AI 在制作阶段批量协助生成。首先建立可复用的任务结构、事实约束和审核流程，再扩充数量。

不以“AI 已生成一千条”代替一千条可玩、无矛盾、有差异的任务。只换人名或数字的变体，不算新的剧情结构。

## 11.2 三种权限

| 用途 | 允许 | 不允许 |
|---|---|---|
| 制作阶段 | 草拟故事、材料、对话、题目、反馈，生成受约束变体 | 未验证就写入主线事实与唯一解谜底 |
| 运行时辅助 | 解释语言、给写作反馈、在已知材料范围内澄清 | 越级泄露剧情、隐藏修改证据或直接执行不可逆选择 |
| 个性化内容 | 选择已验证任务或受严格限制的复习变体 | 自由生成改变主线历史、人物生死或经济平衡的事件 |

首个可玩版本不依赖运行时生成新任务；这一能力只能在固定内容闭环成立之后评估。主线、关键音频、谜题和兜底提示均需有本地可用版本。

进入一个任务后，其事实、材料、答案和规则绑定同一内容版本。维护更新不能让玩家手中的旧录音与新答案互相矛盾。

## 11.3 AI 无权充当最终世界裁判

文本建议、语义提取与语言反馈均是辅助输入。奖励、任务结束、阵营变化和设施状态，必须由受控规则根据玩家确认的行动产生。

AI 不能自行决定“该玩家英语不好，所以失去好结局”。置信不足、服务异常和不支持的任务类型必须有明确状态，不允许假装成功。

# 12. UI、可访问性与数据边界（CORE-12）

## 12.1 最低界面要求

常驻入口至少覆盖当前任务、证据与笔记、材料档案、角色装备、学习记录和设置。最终布局与按键由第十部分制定。

关键文本必须能选取或通过明确入口查看释义，不能全部烘焙在背景图片里。文字大小、字幕、音量和播放速度可调；关键状态不能只靠颜色、极小图标或声音区分。

操作与文本查看不依赖精确反应。场景入口清晰，可交互物件有主动高亮或等效导航方式，不能把找像素当作英语训练。

离开写作界面不得丢稿。长时间返回时，恢复到目标摘要、当前线索和草稿，而不是只展示空泛的“欢迎回来”。

## 12.2 数据政策

默认本地保存，主线不要求注册。联网服务只获取本次功能需要的材料和文本，不默认上传全部写作、存档或个人信息。

用户能查看、导出和删除自己的学习记录，能分别管理冒险存档和学习档案。保留学习事件不意味着无限制保存所有逐键输入；提交文本、草稿和遥测应分开管理。

帮助使用、修改、重复尝试和无障碍路径可以作为学习条件记录，但不贴羞辱性标签，不提供按英语表现压低的剧情人格评价。

这里规定产品边界，不代替上线地区的数据与隐私合规审查；具体技术与发布要求另行确认。

# 13. 范围预算：原型、样章、完整版

## 13.1 三个交付层级

| 层级 | 必须包含 | 明确不包含 |
|---|---|---|
| 机制原型 | 一条小任务闭环；可交互场景；阅读、音频、自由写作；一个机关和战斗；提示、离线判定与草稿保存 | 完整世界、多职业树、大规模事件、正式美术 |
| 第一可玩样章 | 《最后一班渡轮》或同等任务的完整体验；数个场景、一名同伴、路线选择、一次成长、任务结算与学习记录 | 六区域全量内容、完整阵营系统、运行时无限生成 |
| 完整版 | 完整主线、分区域探索、持续成长、同伴支线、读听写覆盖与内容生产能力 | 仍不自动包含多人、3D 开放世界和口语评分 |

第一可玩样章不能只有好看的界面和战斗，真正的听力、写作、帮助标记与故障降级必须已经能用。原型可用占位资源，但不能用假评分伪装学习系统已经完成。

## 13.2 完整版内容预算的处理

暂保留“序章＋六个主要区域＋终章”的规模方向，第二部分可以在明确理由下调整。

此前的约 32 个主线任务、48 个支线、80—100 个场景和其他内容量是估算，不在这里强制冻结。第四、第六和第十一部分需要分别定义任务、谜题、场景变体和英文内容的计数口径，再给出可生产的数量。

数量不能成为主要验收标准。必须优先检查信息依赖、可解性、叙事差异、技能覆盖和重复负担。

# 14. 与其他系统的逻辑接口

本节定义必须保存的含义，不提前锁定引擎、数据库、类名或最终 JSON 字段。技术实现由第十二部分统一。

| 数据领域 | 至少需要保留 | 所属边界 |
|---|---|---|
| 世界与任务状态 | 任务实例、事实与来源、玩家已确认行动、剧情结果、内容版本 | 只有受控任务规则提交改变 |
| 角色成长 | 等级、属性、技能、装备、资源、奖励结算记录 | 不直接读取语言分数计算通关能力 |
| 学习观察 | 玩家档案、能力目标、材料与版本、尝试、帮助、输入方式、观察结果、评价来源 | 记录表现，不直接改变剧情 |
| 临时工作 | 草稿、笔记、打开材料、播放位置、待确认行动 | 不能因切场景或战斗失败丢失 |
| 用户偏好 | 三条难度轴、语言、字幕、无障碍、联网与数据选择 | 不偷偷转为惩罚性规则 |

概念上的调用链为：

```text
玩家操作或提交表达
    ↓
理解或确认行动意图
    ↓
固定任务规则检查事实与条件
    ↓
提交冒险结果与奖励

同次交互的可观察证据
    ↓
记录材料、条件、帮助与评价状态
    ↓
更新学习记录并推荐后续练习
```

两条链通过同一个交互记录关联，但学习服务不得直接写入人物生死、任务奖励或结局。

最低事件记录需能区分内容展示、帮助调用、尝试提交、行动确认、任务结算和存档恢复。重复发送同一次结算不得重复发奖；同一材料重试可以记录新尝试，但不得冒充新材料。

奖励去重针对当前冒险状态中的同一次结算，不是跨所有回档永久锁死奖励。读回结算前的存档后，按恢复状态重新完成任务应正常获得该奖励；不能让玩家既失去回档前的奖励，又被全局记录阻止重新领取。

# 15. 验收规则与验证门槛

## 15.1 可执行的核心验收案例

| 编号 | 测试情境 | 必须得到的结果 |
|---|---|---|
| CORE-AT-01 | 关闭全部联网服务，开始并完成样章 | 主线可推进；写作未评估时明确显示，不产生假分数 |
| CORE-AT-02 | 同一行动分别使用与不使用翻译完成 | 基本任务结果与奖励相同，学习条件记录不同 |
| CORE-AT-03 | 英文表达路线正确，仅有不影响理解的语法错误 | 不自动进入灾难结局，提供语言反馈 |
| CORE-AT-04 | 文本中的否定导致行动含义不确定 | 先澄清与确认，不直接执行不可逆结果 |
| CORE-AT-05 | 起草一半后退出，或完成写作后战斗失败 | 草稿和已完成学习交互保留；只恢复相应冒险检查点 |
| CORE-AT-06 | 不选择感知加点，不带某位同伴 | 仍有取得全部必需线索的可行路径 |
| CORE-AT-07 | 看完整解法后读档，再次提交答案 | 不被记录为陌生材料首次独立成功，不重复发奖 |
| CORE-AT-08 | 开字幕或因音频故障使用文本继续 | 剧情仍可完成；不假报纯听力证据 |
| CORE-AT-09 | 更改战斗难度 | 当前文章、谜题事实、语言评价条件不被连带修改 |
| CORE-AT-10 | 重复点击结算，并分别读取结算前与结算后的存档 | 每条恢复后的冒险状态中恰好结算一次；结算前回档不会永久丢失奖励资格 |
| CORE-AT-11 | 使用合理的另一种写作表达或可行方案 | 不依赖逐字答案；无法判断时进入澄清而非强判错误 |
| CORE-AT-12 | 删除学习档案但保留冒险存档 | 冒险可继续；学习记录显示缺少证据而非虚构重建 |

每项测试应在其相关模块实现后落实为自动化测试或明确的手工验收步骤。核心测试失败时，不靠增加内容掩盖问题。

## 15.2 样章试玩的初始观察目标

首轮可以用约 10 名接近目标能力的玩家做问题发现，不把它当作学习效果实验。

待验证目标是：多数玩家能在不受作者口头指导时说清当前目标；例如先以 8/10 能说明目标、7/10 能利用游戏内支持走通任务作为设计门槛。这些数字是项目阈值，不是研究结论。

同时记录卡住位置、提示使用、重复错误、写作中断和系统误判。没有意识到英语信息与行动关系，即使通关率很高也不视为设计成功。

存档损坏、主线死锁、关键事实矛盾与重复发奖属于必须修复的问题。学习效果的正式研究方案、评价一致性和迁移指标在第五部分细化，不能用满意度或游玩时长替代。

# 16. 设计移交、变更与下一部分

## 16.1 后续部分的责任

| 后续部分 | 必须继承本部分并解决的事项 |
|---|---|
| 2. 世界观与剧情 | 时间线、事实、人物动机、章节、有限分支与结局条件 |
| 3—4. 探索与任务 | 关键线索可达、入口可见、状态与恢复、任务依赖与兜底路径 |
| 5—6. 学习与解谜 | 能力地图、证据标签、难度校准、提示链、可解性与合理替代答案 |
| 7—9. RPG、战斗与人物 | 构筑差异、奖励、战术、关系后果；不破坏语言与剧情解耦 |
| 10—11. UI 与内容 AI | 可访问交互、内容生产、事实检查、受限辅助与版本一致性 |
| 12. 技术架构 | 引擎与资源方案、完整数据契约、持久化、可选评价接口及测试落地 |

## 16.2 交给 Codex 时的使用规则

本文件作为全局约束输入，不能单独用于推测并生成整款游戏。相关模块尚无详细规格时，不允许为了填空自行发明技能公式、剧情结局或评分算法。

后续每个开发任务必须注明引用哪些 CORE 规则，读取哪些专项文档，允许修改什么，禁止改动什么，以及通过哪些验收案例。可调初值放入配置，不散落在各模块中重复硬编码。

技术尚未定案的事项保持显式待定：引擎、探索移动的具体实现、类与接口名、存档格式、内容格式、评价服务与语料授权方案。待定不代表 Codex 可自由决定，应由对应设计部分先给出答案。

## 16.3 变更规则

变更至少记录：规则编号、原决定、新决定、原因、受影响的文档与验收测试。数字微调与产品方向改变分开处理。

本版最终确定的是：**英语必须参与真实行动；三种进度不互相冒充；帮助与离线不能导致死档；剧情后果来自确认的选择；大量内容建立在固定事实和可验证规则之上。**

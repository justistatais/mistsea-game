# 第十部分：UI、交互与学习辅助系统

文档：`UI_UX_Spec.md`  
版本：`v0.1`  
项目：《雾海档案：第七座灯塔》  
依赖：第1—9部分；英语难度以第5部分及`CR-EN-005-001`为准。  
配套：`data/UI_UX_Reference_v0.1.json`、离线HTML结构演示、`validation/`、`Codex_Handoff_Part10_v0.1.md`。

## 效力与实际交付边界

本文把现有系统组织成玩家能实际使用的页面、输入模式、反馈与恢复流程。规则未特别标注时作为本版UI基线；尺寸、字号、快捷键、槽位数、推荐数量和试玩门槛都是原型初值。引擎、最终类名、UI框架、磁盘事务及在线服务由第十二部分定案。

本轮设计24种页面/视图类型、18个共享组件、15组默认按键行为。它们不是24套独立软件，不新增地图或任务。配套离线HTML只演示文献、草稿、辅助确认、保存提示与Q-102简化状态，不是正式游戏、完整自由英文理解器、音频播放器或战斗实现。首次加载和演示过程中保持这一说明。

**英语目标固定为IELTS Academic阅读、听力、写作各6.5。** 本部分不改写已固定英文材料，不新增分数门槛，不声称样稿已完成校准。字典、字幕、翻译、放大和操作辅助不是要购买的能力。24种视图的完整登记见附录A，正式验收见附录D。

# 1. UI要解决的四件事（UI-01）

玩家应随时分清：**当前目标是什么、已经确认了什么、下一步可以做什么、刚才的操作有没有真正完成。**

界面不替玩家完成推理，也不能让他在“我是在编辑、确认还是执行”之间猜测。首要改进点是把草稿保存、语言反馈、行动意图、物理准备、世界回执和学习证据分开显示。

| 玩家看到的状态 | 权威依据 | 不等于什么 |
|---|---|---|
| 草稿已保存 | 当前正文版本收到本地持久化确认 | 已发送、已评估或已执行 |
| 方案已确认 | 玩家确认了当前版本的行动意思 | 设备已经准备好 |
| 当前准备就绪 | 相关设备、许可和检查仍有效 | 已经离港 |
| 行动已执行 | 世界提交回执 | 所有英语目标已掌握 |
| 反馈可查看 | 对应正文版本的评价返回 | 官方IELTS成绩 |
| 待验证 | 证据不足、条件受辅助或尚无可靠评价 | 0分、失败或失信 |

普通交互减少确认次数，重大结果明确确认。读取一则便条不能弹三次“是否继续”；发送私人资料、消耗预留物资、最终起航则不能只靠一次误触。

# 2. 六个稳定入口与页面结构（UI-02）

## 2.1 全局入口

| 入口 | 内容 | 默认键（仅非文字输入模式） |
|---|---|---|
| 地图 | 世界、区域、已知路线、安全返程点 | M |
| 事务 | 任务、通信、工作单、协议与承诺 | J |
| 档案 | 已取得材料、阅读/听力、证据板、笔记 | B |
| 队伍 | 角色、技能、收藏、装备、同伴与已知联系人 | C |
| 学习 | 分技能记录、复习、目标练习与独立检查 | L |
| 系统 | 存档、设置、帮助、数据与退出 | Esc到系统层 |

探索和战斗是当前世界视图，不各自再增加一套“背包、论文、关系”等入口。通信正文的规范入口属于事务；文献、人物或任务中的“继续写作”均传入同一个任务/草稿ID。商店由场景对话打开，仍使用共享交易组件，不要求永久放一个商城按钮。

所有入口均有文字与可辨图形，不只用神秘符号。可折叠导航在窄屏也必须保留文字说明和键盘访问。新功能可以在实际建立任务时显示用途，不能预先列出未相识人物、未获得材料和隐藏结局条件。

## 2.2 深链接与返回

典型往返：任务→引用材料→词义→材料原位置→原任务。阅读和编辑切换恢复各自滚动、段落、光标和筛选；返回不是重新载入任务。保存的是可见工作状态，不复制领域事实。

同一任务经三个入口打开写作，只有一份规范草稿。角色笔记是另一种明确命名的对象，不让它与发送正文互相覆盖。跨任务引用必须标明来源；不能把Q-102草稿误发送成另一封信。

## 2.3 不把未发现内容泄露在目录里

先按当前冒险、角色访问许可和内容版本过滤，再搜索、计数、排序、生成缩略图、tooltip和读屏名称。隐藏文本不能只是CSS透明；未授权内容不能出现在可访问树、复制结果或搜索建议中。

不显示“已找4/7线索”暗示三个秘密。可写“当前档案有4份已取得材料”。人物卡不列未知NPC剪影及完整姓名。独立学习历史可以保留实际表现，但旧分支不能打开未来剧情原文；显示“来源在当前冒险尚未取得”，不暴露材料标题所含秘密。

# 3. 视觉、布局与文字初值（UI-03）

## 3.1 方向

采用克制的档案与航海工作台风格：深色框架、浅色长文纸面、少量强调色、明确边线。提供浅色、深色和高对比主题。地方氛围来自场景与立绘，不让每个地区更换基本按钮位置和交互含义。

图标加文字，状态再配符号或形状。红色不代表唯一可识别的错误，绿色不代表唯一可识别的成功。正文不覆在浓雾、动画水面或复杂纹理之上。UI不使用IELTS官方徽章或“官方认证”装饰。

## 3.2 数值初值

| 项目 | 初值 |
|---|---|
| 布局基准 | 1280×720逻辑视窗；另测1920×1080、16:10和超宽屏 |
| 安全边距 | 基准24逻辑像素 |
| 正文 | 中英文20，行高1.65；字幕至少同等可调 |
| 次级说明 | 18为常用，最小16，不用小字号藏关键限制 |
| 标题 | 28—32 |
| 按钮 | 高度至少44，图形按钮有等价名称与焦点框 |
| 字号档 | 100%、125%、150%、175%、200% |
| 正文行长 | 独立长文约60—80个英文字符的舒适目标，不硬截断句子 |
| 过渡 | 120—180毫秒的表现初值；减少动态时可取消 |
| 双栏条件 | 有效逻辑宽度至少1100且字号低于150%；否则改分区/单栏 |

上述是产品原型目标，不宣称通过任何无障碍认证。允许调整字号和行距，不因文本变长自动缩回到小字。200%模式必须能看见按钮、错误、目标和完整文字，采用重排与滚动，不要求所有内容仍在一个屏幕。

## 3.3 写作与阅读的参考布局

1280×720、默认字号：页头(24,16,1232,48)；写作左侧来源(24,80,480,552)，右侧编辑(528,80,728,552)，操作区(24,648,1232,48)。阅读则正文824宽，帮助384宽，中间24间隔。矩形是参考，不要求正文固定在552高的裁切框中。

窄屏或大字时，“材料/正文/反馈”成为可切换区域；保持同一草稿与两个独立滚动位置。操作区进入文档流，不能固定覆盖最后一行。宽屏增加留白与比较宽度，不把一行英文拉到整个3440屏幕。分屏拖动是可选便利，所有功能有按钮和键盘方式。

## 3.4 场景坐标与UI坐标分离

沿用第三部分场景0—100局部坐标。鼠标先命中UI层，未被消费的事件才使用当前画面变换逆映射到场景。缩放、信箱留黑、相机平移和系统显示缩放改变后，都重新计算；不能把1280设计稿像素当世界位置。UI覆盖区域不可点穿，切层时丢弃旧排队移动。

# 4. 输入模式、焦点与防误触（UI-04）

## 4.1 唯一输入拥有者

探索、接近目标、工作区、文字编辑、对话、谜题、战斗决策、战斗结算、确认和迁移分别声明输入模式。顶层只有一个拥有者；阅读可在战斗之上打开，但不会让按键同时攻击。

输入分发优先级：**输入法候选/组合→当前可编辑控件→最上层弹窗→当前工作区→场景热键**。文本选择、搜索框、数量输入和备注也属于编辑上下文，不能只保护作文大框。

## 4.2 默认键鼠

WASD/方向键仅探索移动；Tab/Shift+Tab循环当前层可交互对象，E或聚焦对象上的Enter发起接近与操作；H切换对象高亮。所有关键按钮可经焦点到达。鼠标悬停只是便利，不能独占说明。

编辑中Enter换行，Ctrl+S请求保存，Ctrl+Enter默认不绑定发送。普通粘贴可用，不用剪贴板行为给玩家贴人格标签。文本内M/J/B/C/L不切页，数字不选技能，空格不播放另一段录音。

战斗1—4选择对应主动但不自动找目标执行。Esc先取消选靶，再关闭资料层，再到系统；保留已有可见候选。角色队列不可拖动以绕过先手。

## 4.3 输入法与按键边界

组合输入期间Esc先交给输入法；Enter接受候选但不提交动作。组合结束后，在编辑控件里按Esc先退出该编辑焦点，再按Esc才返回上一工作层，不删除正文。接受候选后仍须一次新的明确输入才能操作按钮。按键重复、旧页面的keyup和一次点击的pointerup不得穿透新页面。

输入层变更增加交互世代号，清空旧命令队列。pointerdown与pointerup必须属于同一有效上下文、对象与手势。按住Enter关闭对话，不能下一帧按下“确认离港”。组合状态不能只依据英文按键名判断。

## 4.4 弹窗与焦点返回

每个弹窗记录发起控件；打开后焦点进入弹窗，背景不可操作；关闭后回到仍存在的发起控件，否则回到对应标题。不可逆确认默认焦点是“返回检查/取消”，不是执行。Esc通常可取消；正在等待未知提交结果时只关闭表现/返回记录，不假装撤销已提交世界。

错误摘要可聚焦并跳到具体字段，不能把焦点扔到页面顶部。提示抽屉可叠在工作区上，但不堆叠多个同级确认；最上层帮助关闭后只解除自己的暂停租约。

# 5. 暂停与声音（UI-05）

阅读、写作、比较、对话中的思考和系统菜单均不推进惩罚性世界时间。多层工作区使用独立暂停持有者：关闭词典后，下面的写作仍保持暂停；最后一层关闭才恢复。不会补算暂停期间的巡逻、护送和持续伤害。

声音区分主音量、内容语音、环境、音乐、UI音。一次只播放一条主信息语音；打开另一条先暂停前者并保留位置。词音示范需要时暂停主录音，结束后由玩家明确继续，不偷偷跳过原句。减少环境声不计作内容帮助。

切出应用、失去音频设备、音轨失败时暂停内容播放并显示真实状态。不能继续走隐藏播放计时却写“已听完”。字幕不依赖音轨加载成功；无音轨时可显式改读脚本，按真实模态记录。读屏播报不与线索语音争抢同一声道，需提供独立读屏导航与暂停。

战斗动画快慢只改表现，不改变模拟回合、冷却或伤害。动画跳过读取已提交结果，不再次执行动作。

# 6. 首次进入、继续与教程（UI-06）

## 6.1 首次进入

最短路径：选择/建立本地玩家档案→字号/字幕/输入初设→显示训练目标6.5与非官方成绩说明→开始序章。短诊断可跳过，不阻止游戏，不强制注册、联网、麦克风或摄像头。

默认中文系统界面、英文剧情材料、按需中文解释。音频字幕遵守首次设置；选择始终字幕的人不会被系统为了训练暗中关掉。训练模式和真实支持条件说明只在需要时出现，不每次打开词典都弹警告。

## 6.2 教程分散在实际操作中

序章教移动、明确出口、检查、保存和短求援；第一章教材料比较、重播/字幕、草稿与行动确认；首次战斗教意图和行动点；后续首次进入技能、工作单、协议时再介绍对应操作。

每张教学卡可关闭、以后在当前帮助中重开。理解已经表现出来时不强迫再按规定顺序做一遍。教程不通过遮住所有出口强迫读完长文。

## 6.3 返回摘要

继续时显示实际冒险槽的场景与阶段、最近确认的结果、正在处理的目标、未完成草稿和上次工作位置。返回摘要只包含当前分支允许的内容。

示例：已取得替换支架；导航灯尚待当前配置检查；给哈文的说明有草稿。不要直接补写尚未推导的航道结论，也不显示“英语进度落后7天”。摘要可跳过，不重复奖励。

# 7. 探索HUD与地图（UI-07）

探索常驻仅保留位置/返回方向、一项主要目标、最多两个相关子目标、队伍入口、当前交互和六个全局入口。无战斗时不长期展开三人的全部状态图标。正文、装备、任务日志不同时铺满场景。

点击对象先到合法操作点，键盘选择使用同一路径。物件说明、门禁原因和预计动作先于不可逆操作。普通拾取与开已开放门不多弹确认。隐藏物的调查不依赖难以察觉的单像素。

地图明确区分“听说”“已到访”“已登记安全返程”“当前不能旅行”。当前运输不能被快速旅行瞬移；显示退回或安全托管入口。反方向出口不会在生成角色时立即触发。

地图材料仍在档案内，不能被导航地图自动改成答案标记。玩家画的路线使用“我的计划”，实际通路依设备、权限和现场状态核验。

# 8. 任务、资料目录与来源（UI-08）

任务日志显示发起缘由、当前工作、已确认结果、可调查方向、暂停/恢复与已知阶段窗口。不要求检查所有已读框，不显示未知支线总数。未满足条件要分成设备未就绪、需要澄清、无访问权限、系统数据不可用等，不统写“失败”。

材料目录按任务、类型、取得顺序和玩家自加标签检索。阅读/听力图形后附文字；复制引用带来源，已取得同一文档的副本保留同一来源根。原文时间与获取时间分别显示，避免把抄录时间误当事件时间。

加载中保留最后合法页面但禁用相关提交；空目录说“尚未取得材料”，不是系统错误；错误保留工作并提供重试/返回/本地已缓存版本。隐藏章节标题不能出现在错误路径中。

# 9. 阅读、词典与翻译（UI-09）

## 9.1 阅读器

常驻标题、来源、原文版本、段落、返回。正文可选择，可按段落和语义阅读顺序键盘访问；左右比较各有独立滚动。按字体缩放重排后用段落ID与文本锚点恢复，不用旧屏幕像素猜位置。

页内查找不把未授权版本一起搜索。通过任务引用进入时定位原段，不自动高亮最终答案。必要引用有“返回原文”，不能只剩脱离语境的一小句。

## 9.2 词典

选中词/短语后可查看适用词义、搭配、简明中文、词音和个人笔记。先显示当前语境可支持的词义，不把整段谜底混进释义。专有设定词可以直接定义，不伪装成读听能力成绩。

选择范围保存材料ID/版本、段落ID和明确的Unicode代码点范围；引擎处理代理对、组合字符和缩放，不拿字符宽度作为文本索引。鼠标划词以外提供段落-词项焦点与整段查看帮助的方式。

## 9.3 翻译与提示

三类帮助入口并列：操作、语言、逻辑。语言为词义→句法→分句→全文译文；逻辑为方向→关系→局部结论→完整方案。玩家可直接请求较深层帮助，不扣资源。

帮助在实际显示、播读或复制出相关内容时记录范围；预取内容、隐藏面板和仅显示按钮不算已经阅读。系统只能记录可观察条件，不宣称知道用户是否看懂或使用另一台设备。

译文标为辅助译文并对照原文；不把动态生成解释写回规则文本。关闭后回到原选择与焦点，当前任务和奖励不变。完整解法可能影响相应独立证据，不回溯抹掉之前已提交的表现。

# 10. 听力工作区（UI-10）

播放器显示实际音轨状态、当前位置/总长、播放暂停、前后跳转、A/B复听、速度和字幕。默认1.0，冒险中可选0.75/0.9/1.0/1.1/1.25；这只是播放控制初值，不是6.5官方语速。改变速度记录实际条件，不改敌人或奖励。

字幕开关始终可见，正文默认是否显示遵守用户设置。禁止一打开音频页面就把全文字幕放进隐藏可聚焦区域或读屏自动摘要中，再记录首次纯听力。已经显示/播读的同事实信息计入实际条件，不凭播放次数伪造独立。

切换场景、查词或稍后再听时保存播放位置。主音轨缺失：明确显示“音轨尚不可用，可查看脚本”，不生成假进度，不使用未经说明的TTS替代正式听力。脚本可以继续任务，但本次相应内容记为文本输入。

录音不自动播放与同一页面另一段语音重叠。用户选择脚本后展开对应说话者和原文，不追加作者推断。字幕时标由成品音轨对齐；本轮没有音轨，不能假装已核验精确时间戳。

# 11. 证据板与六种谜题控件（UI-11）

证据板分为原文引用、人物说法、我的假设、已确认行动四种明确卡片。引用卡保留出处、来源根、版本与原文锚点。玩家拖一条线只创建“我的联系”，不把事实写入世界。

大板可以按案件分组，但本轮不做一块需要无限缩放才能找到线索的空间。所有卡片有顺序列表视图。拖拽的键盘替代是选择卡片→选择放置区/关系→确认；放错后可撤销。

| 控件 | 非拖拽操作 | 特别规则 |
|---|---|---|
| 版本/来源比较 | 选左右材料、逐字段比较 | 不自动认定最新文件覆盖一切 |
| 时间/步骤轨道 | 选事件，上移下移或指定位置 | 接受合法偏序，未知时间可留未知 |
| 证据地图 | 选地点/边，加入或移除计划 | 一条旧桥与新通道是不同连接 |
| 分配表 | 选物资、选批次、预览剩余容量 | 编辑不预留，不接受隐藏的唯一偏好 |
| 实体设备 | 选对象、动作、合法站位 | 操作真实设备，不用答题正确代替安装 |
| 沟通编辑器 | 正常输入与当前意思澄清 | 同任务共用正文，不重复加作文 |

验证结果要说明其范围，例如“当前分配满足容量与先后要求”，不夸大为“全部工程完成”。异常时保留草案，不能清空卡片逼玩家重做。

# 12. 写作工作区（UI-12）

## 12.1 三个区域，一份正文

左侧显示已获材料与可固定引用；右侧是规范草稿；反馈在独立页签/抽屉中。小窗口改为“材料/写作/反馈”切换，不建立多份稿件。

顶部显示任务、接收对象、目的和正文版本；中部编辑；底部依次提供保存状态、参考词数、核对方案、请求语言反馈。两种动作明确分开。参考词数对数字、连字符和撇号采用稳定规则并说明仅供写作参考，不声称等于官方计词。

短消息不显示完整band评分入口。Task 1/2式完整任务按第五部分显示自己的要求；普通留言不继承150/250词限制。无统一计时、无默认强制拼写纠正。接受约定英美变体，润色建议不能暗中改变事实。

## 12.2 可接受的编辑行为

选取、复制、粘贴、撤销、重做、标点、换行和输入法正常工作。引用原文可带来源插入笔记，插入发送正文前明确动作。使用模板或接受改写记录受影响的范围；不以“出现高级词”自动提高评价。

反馈采用“原句—问题—理由—可选改法”，需要玩家选择才能写回。不要全文红线，不把每个风格偏好当成错误。默认一次呈现最影响意思的1—3类问题，其余可展开。修改后形成新版本，不覆盖旧评价所指的文本。

## 12.3 线上能力与离线通路

首次请求在线反馈前说明发送哪份正文和必要上下文，可取消；不把打开写作页当同意上传。缺少服务时保留自由输入和本地基础帮助，通过显式结构化确认继续任务，状态是“行动可确认；写作尚未评估”。

UI不得使用关键词检索声称理解全文。配套HTML的路线与步骤选择是**结构化辅助演示**，永久显示未连接语言理解；它不把非空文本当合格英语。

# 13. 草稿保存、异步反馈与多窗口（UI-13）

## 13.1 保存状态是真实回执

已提交编辑内容以约500毫秒去抖请求保存；正常离页/退出先完成当前已提交输入并刷新保存。输入法尚未提交的候选不上传、不评价、不冒充最终正文。突然终止进程可能丢失系统输入法仍持有的预编辑内容，这项边界需要实际输入法测试。

状态包括“有未保存更改”“保存中”“此版本已保存在本机”“保存失败，仅本次会话保留”。只有收到当前正文版本的持久化确认，才能显示当前稿已保存。旧版本的延迟确认不得覆盖新正文或把它标成已保存。底层需要按版本串行/比较更新，UI的打勾不等于实际磁盘事务。

继承CORE的异常丢失约5秒目标，但不声称覆盖全部硬件故障。磁盘满、目录无写权限或浏览器存储受限时显示原因与导出文本、重试、继续本次会话；离开可能失去未存文本时明确提示，默认留在编辑器。

## 13.2 晚到反馈

反馈绑定档案、冒险上下文、材料、草稿版本、请求和评价版本。旧稿反馈进入“对应旧稿”，不抢当前光标、不替换新稿、不自动提交方案。删除学习档案提高删除世代号，旧结果不得重新写回被删除内容。

## 13.3 同一稿多入口与多实例

同一进程内的多个入口引用同一草稿。多窗口/多实例发现其他写入者时显示冲突并只读或要求明确接管，不能静默最后写入覆盖。可保存冲突副本供人工比较，但不能把两个正文各自误当成已发出的主线命令。

结构演示采用浏览器本地存储，不保证不同文件路径或浏览器之间共享。它只保存演示稿和设置；需要时提供导出。正式引擎的单写者、原子文件与崩溃恢复在第十二部分实现。

# 14. 确认、执行和未知结果（UI-14）

## 14.1 不混在一个“提交”按钮里

普通阅读/移动不确认；有多种意义的设备显示动作菜单；战斗选技能后选目标并预览；重要世界行为使用专门确认卡。通信中的“保存草稿”“核对方案”“请求语言反馈”“预览并执行”各有清楚名字。

意思可以先确认，设备之后完成。最终执行预览读取当前设备与最新检查，不要求每装一个零件重写文章，也不能因为文章已确认就视设备为已修复。

## 14.2 通用确认卡

显示：行动对象；本次确切操作；消耗或转移；影响的对象；可逆程度；当前相关条件；执行后玩家所在位置；明确按钮。如Q-102显示“民用渡轮载NPC离港；你留在渡运广场；支架与电池随船；不会自动进入第二章”。

不在卡片里新增用户没选择的立场、不默认勾选对外公开。私人资料还显示字段、接收者、用途、许可版本和正文可能包含的受限内容。不能只查附件而忽略正文。任意正文无法可靠核验时转为受控字段文本或澄清。

## 14.3 版本与单次提交

预览绑定任务/对象、设备配置与检验、提案/确认、许可、规则和当前加载上下文。相关变更失效并展示差异，无关查词或来信不失效。没有现实倒计时。

点击后进入“正在核对并执行”，禁用同类重复动作。超时不等于失败；先查同一提交回执，显示“结果待确认”，不能换新请求再次发船、扣费或派工。若已提交，读取结果；若明确未提交，允许使用原意图重新预览。关闭表现卡不撤销已提交事实。

配套原型只有本地同步模拟，不证明真实引擎事务已经完成。

# 15. 战前、战斗HUD与结果（UI-15）

## 15.1 战前

展示真实入口等级/校准、主角构筑、两席援助、两次共享急救、两增强补给格、已知敌人与任务目的。Q-102按3级/校准0，Q-104按5级/校准0，不借用结算后奖励。

未招募莉娜时不把她偷偷塞进工坊队伍。空援助席给地方援勤入口；主动坚持单人时说明是自选条件，不修改地图谜底或学习难度。

## 15.2 战斗布局

上方当前轮与双方队列，中央四位置战场和场地装置，侧方当前意图，底部当前角色基础动作与4主动/2专属。当前行动者高亮并有文字姓名；先手顺序只读，不允许拖动绕过规则。

角色卡同时区分HP、护盾、AP和专注。稳定条显示压力/阈值、恢复保护和解除条件。普通状态显示来源、次数、真实到期边界；不用几秒倒计时解释回合制冷却。

例：“CD1：下一次自身行动不可用，再下一次可用”；护盾说明“到来源角色第二个后续计划槽开始”；可展开为当前队列对应位置。倒地不会暂停逻辑时钟。读写窗口关闭不会重置计数。

## 15.3 目标预览

人物锁定用目标姓名与人物标记；列锁定明确左/右列；全场用范围标识和文字。颜色只是辅助。显示原始威胁、现有防护后生命损失、护盾吸收、机制锁护和可中断性质。

已知确定结果可以给数值；有未决触发时用明确范围或“不含尚未确定效果”，不编造精确值。所见敌人意图不会因玩家按防御偷偷换目标。选择非法目标不花AP。危险确认与普通目标选择区分，不每次普攻再弹完整离港式警告。

资料/词典在战斗决策上层打开。关闭回原角色与未执行的选择，若相关状态确实改变则重新预览。战斗中队伍面板只读，不许洗点、调换实物或领取新遭遇配发。

## 15.4 结果

“威胁已制止”和“任务已完成”采用不同标题。工坊胜利后可继续取件，塔站胜利后按实际工作交接；没有杀敌经验再叠任务奖励。战败显示恢复范围、战前整备、重试/撤回，不要求重读材料或重写草稿。动画跳过不跳过结算，也不重复结算。

# 16. 构筑、装备、交易与人物（UI-16）

## 16.1 构筑

分开展示等级、下一门槛、点数、阶位与校准，不使用“综合战力”代替解释。点选属性即时预览当前构筑差异；专注等阶梯收益显示距离下一点容量的条件。技能树显示费用、前置、层级、冷却语义和当前可装备槽数，不隐去无法学习的具体原因。

安全处候选整套预览与提交；失败时旧构筑保留。离页未提交可以保存方案或丢弃候选，不能扣掉实际点数。战斗中禁改有可聚焦原因，不能只灰掉。

## 16.2 收藏与改件

按当前校准比较同类装备，显示装在哪个角色、型号和唯一实例。把米拉的遗物给主角时明确“一并从米拉卸下”，原子执行，不复制。个人物品、任务物品、工程账分别管理。具名收藏不可出售且说明原因。

## 16.3 商店与制作

显示数量、单价、总价、拥有量、剩余资源、I级/II级原件去向。预览不扣钱；确认生成一项交易。背包空间不足按第七部分的保管规则，不销毁奖励。提交结果未知时先查回执，不能点一次“重试”再买一份。

## 16.4 人物

人物卡使用工作合作、私人交流、具体议题三个视图，给当前分支允许显示的最近依据，不显示“好感73”。同时显示在船/随队/地方工作/可通信等实际状态。私事需要当事人同意；值班人员可以代收工作请求，不代替本人同意见面。

# 17. 工作单、六地区与最终起航（UI-17）

以地区/工作单为主，不把五个组织排成六个好感条。列出库存、预留、运输中、已交付、已安装、试运行和被接受的协议版本。基础安全、本地保全、增强准备分别标示。

缺项提供“查看真实来源/查看占用班组/继续下一工作步骤”。派工不是完成，材料到账不是安装，安装不是验证。签字按地区的操作与代表职能显示，不把一个人的签名复制六次。

UI-71在Q-604合法阶段公开当前可执行方向和缺项。进入前明确尚未完成且会受影响的已知工作、是否可补、返回方式及起航后限制。没有条件不足时的隐藏按钮；也不把未发现个人支线名单全剧透出来。

起航确认保留真实检查快照与存档。终局UI-72在现场已经稳定后使用这一准备基础；允许保留价值分歧，不增加语言分数或同伴任务门槛。最后命令在安全状态下写，不带战斗伤害倒计时。

# 18. 学习页与辅助设置（UI-18）

顶部显示“训练目标：读/听/写6.5（不是当前成绩）”。阅读、听力、写作分开显示证据不足、借助支持、本次独立、多情境、延迟验证和建议复核。每项可追溯到材料、尝试、时间和工具条件。

不用百分比雷达图暗示精准能力，不拿短任务生成完整雅思分。尚未评估写作不显示0分，听力音轨失败不加入错误分母。自动纠错、引用范例和同事实先验暴露按相关范围记录；UI只呈现第五部分的投影，不自行发明算法。

复习最多推荐三项，不做欠作业红点。允许稍后再做；主线、装备与结局不受影响。独立检查进入前显示素材范围、允许工具和是否计时；选择暂停、字幕或其他支持后可继续，记录真实条件。严格计时条件改变，显示非标准计时条件，不隐藏暂停记录却宣称考试等价。

三条设置独立：战斗参数、谜题支持、语言辅助。字号、按键、声音和动态另列。战斗中改战斗难度需要明确退回入口按新参数开始，不保留旧模式已经打掉的HP；设置界面不能直接修改当前敌人生命制造便利。

# 19. 存档、恢复、导出与删除（UI-19）

## 19.1 存档页面

初值为6个手动槽、5个滚动自动槽，重要不可逆阶段前另有受保护保留点；自动槽不覆盖保留点。每个显示玩家档案、冒险分支、场景/阶段、实际保存时间、内容版本与最近结果。缩略图必须遵守当前档案权限，不能把另一玩家内容带进来。

“草稿已保存”和“冒险已保存”分别显示。保存设置不使冒险槽显示新日期。读取预览说明当前尚未保存工作，默认先保留；加载损坏槽提供其他合法槽和恢复路径，不悄悄跳到另一档。

## 19.2 返回与兼容

读取后恢复可用材料、草稿、光标、音轨位置与局部工作。不能恢复过期的未执行确认token；需要重新预览实际行动。战斗继续保留原消耗/回合/冷却，不当新遭遇。

正文版本变化、原引用段落被迁移时标出无法精确恢复的引用，并保留原记录供对照，不把高亮放到碰巧相同像素的位置。旧版剧情文本和规则不能半新半旧混用。

## 19.3 数据范围

分别提供：导出冒险槽、导出自己草稿、导出学习记录、删除指定评价副本、删除学习档案、删除草稿、删除整玩家档案。显示会影响和不会影响的内容。

删除学习档案不会抹掉当前冒险设备与已经成立的世界回执；冒险规范草稿是否保留单独说明。用户选择“删除正文与评估副本”时需要同时定位相关存储，不能删除显示卡却留下可恢复正文。旧异步反馈不得灌回已删除档案。

数据默认本地，联网评价是可选功能。调试遥测不能偷偷上传正文、姓名、证词或逐键记录；错误日志默认只记录必要版本、动作类和错误码。实际隐私政策与服务持久化交第十二部分核验。

# 20. 通知、错误和恢复文案（UI-20）

## 20.1 通知不抢输入

保存回执在原控件内更新，语言反馈在对应页签显示待查看，来信进入通知日志。主线也要等安全交互点，不能把“高优先级”解释成可以关闭输入法或覆盖正文。

同屏最多一条短通知，其他合并入日志。重复事件不重复声音。首次重要教学可短暂停留，玩家可关闭；通知不靠几秒后消失的唯一文字传达必要信息。屏幕阅读器的实时播报去重、延迟至安全边界，不能每输入一字朗读保存状态。

## 20.2 文案样例

| 配置使检查过期 | 电池连接已改变，需要重新检查导航灯。 | 返回设备 |
| 许可撤销 | 当前接收范围已改变，这份预览不能发送。 | 查看差异/重新核对 |
| 世界结果未知 | 正在核对这次行动的回执，请勿重复发起。 | 查看记录/继续核对 |
| 无当前可见材料 | 尚未取得可在此查看的材料。 | 返回探索 |
| 已确认事实之外的新提案 | 这项操作不在当前任务支持范围内。 | 保留笔记/选择可执行安排 |

原文负面情况按事实说明，不写“你的英语太差”“你作弊了”“好感不足”。内部异常代码在可展开的诊断中，默认说明实际影响与安全下一步。

# 22. UI程序契约与安全投影（UI-22）

## 22.1 最少保存的展示上下文

`player_profile_id`、`adventure_id`、`load_context_epoch`、`screen_id`、`source_route`、`focused_control_id`、`material_id/version`、`paragraph_anchor`、`draft_id/revision`、`panel_tab`、`scroll_anchor`、`audio_position`、`candidate_id`、`pending_command_id`。

其中正文归规范草稿库，物品归实例账，学习观察归学习系统，UI只引用，不复制权威世界状态。来源权限在数据投影入口过滤，不能指望每个组件各自记得隐藏所有秘密。

## 22.2 读与写接口

| 类别 | 建议契约 | 作用 |
|---|---|---|
| 查询 | `get_view(context, permissions)` | 只返回当前允许显示的数据 |
| 文稿 | `save_draft(id, revision, body)` | 持久化当前已提交编辑，不发通信 |
| 预览 | `preview_action(intent, versions)` | 返回确切后果与相关版本，不写世界 |
| 执行 | `commit_action(token, command_id)` | 交由对应权威系统核验并提交 |
| 结果核对 | `get_receipt(command_id, goal_key)` | 处理响应未知和重复投递 |
| 学习 | `record_support(scope, time, modality)` | 真实帮助条件，不自动判掌握 |
| 焦点 | `push_layer / pop_layer` | 同步输入拥有者、暂停与返回点 |

这些是语义建议，不提前选择引擎API。渲染器不运行模型输出中的代码，不以未转义HTML呈现玩家正文或生成文本。表面看似不可点的按钮仍可能被键盘或脚本请求，权威系统必须再次验证。

## 22.3 每个页面都要有状态矩阵

正常、空、加载、失败、只读、过期、恢复、提交中、结果待确认各有明确表现与合法动作。不是每页都要出现全部状态，但定义必须说明哪些适用。占位版不支持的功能显示“未接入”，不放会产生假评分或假任务回执的按钮。

# 24. 验证、试玩门槛与本轮限制（UI-24）

本轮实际运行的检查数、浏览器版本、场景、分辨率和结果见`UI_UX_Validation_v0.1.md`与机器报告。代码中的参考模型是有界UI逻辑，不是整个游戏状态机。浏览器测试只覆盖配套HTML已经实现的部分，不证明24种生产页面全部完成。

正式需要在1280×720、1920×1080、大字模式、窗口切换、中文输入法及不同辅助技术上验证；要测试播放器加载失败、文件系统拒写、正文旧反馈、当前受限资料和提交响应丢失，不只测试一路成功。

可用性首轮以8—12名目标玩家为初值：观察是否能够找回原文/草稿、区分保存与执行、理解敌人锁定、使用帮助而不迷路。初步门槛为80%不需口头指路完成上述关键导航，重大误发、输入穿透、丢草稿、秘密泄漏和重复结算为阻断性问题。小样本只能发现可用性问题，不证明学习提升或统计普适性。

本轮没有正式音轨、真实游戏引擎/存档适配、语义评分、完整NPC前景调度或目标组试测；原生IME与真实读屏也必须另外测试。网页里的合成composition事件通过，只证明对应事件处理分支，不等于所有系统输入法都兼容。

## 本部分的最终原则

**让玩家知道下一步能做什么，但不替他推理；让帮助随手可用，但不伪造学习表现；让正文、方案和世界执行分别有清楚状态；让界面能返回、能保存、能恢复，而不是靠重做掩盖错误。**

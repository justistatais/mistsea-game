# 第十部分 Codex交接

## 先读

`UI_UX_Spec_v0.1.md`、`CR-UI-010-001.md`、`data/UI_UX_Reference_v0.1.json`、`data/UI_Acceptance_v0.1.json`。上位文档精确哈希在`references/Source_Manifest_v0.1.json`，正式集成时使用项目中对应文件，不根据文件名想象其内容。

## 本包是什么

UI规格、页面和组件登记、输入与回执参考模型、Q-102原文引用和离线浏览器结构示例。它没有真实世界服务、自由英文理解、实际战斗、成品音轨或原生存档模块。`ui_reference.py`是受限演算，不是生产引擎。HTML的设备勾选是明显标注的测试夹具，正式版本必须换成真实场景与设备回执。

## 首批可开发任务

1. UI-DEV-01：实现带权限过滤的导航壳、6个稳定入口、24种视图的路由登记。未实现页明确不可用，不造结果。
2. UI-DEV-02：实现输入拥有者、键盘焦点、IME、暂停与层切换。重点跑UI-AT-03至10，不允许字母移动或回车误发。
3. UI-DEV-03/04：复用原材料版本，做可选取阅读器、真实音轨状态、帮助范围和规范草稿。先保证保存回执与失败，不先接评分供应商。
4. UI-DEV-05/06：把Q-102查询、候选、核验、回执接口接入现有地图和任务；删除演示夹具入口，保持单次结算。
5. 之后再完成战斗、构筑、人物、工程、学习和最终起航。使用第八部分真实战斗规则，不让UI自行计算不同的HP、费用和队列。

## 具体依赖接口

查询：当前允许显示的材料/人物、真实任务状态、当前队伍与配置、装置检查、世界回执。

命令：按相关版本生成预览、确认行动、查询结果、规范草稿保存、个人偏好更新、学习支持事件。

所有命令都保留对象、内容和加载上下文。不得让渲染器直接把`quest_done`、`mastered`、`ship_departed`或`relationship_score`写成true。

## 运行参考检查

```bash
python -m unittest discover -s validation -p test_ui_reference.py -v
```

浏览器检查需要当前环境已有Playwright与Chromium；无需联网。脚本支持`CHROMIUM_EXECUTABLE`环境变量；未设置时先用本机chromium，再使用Playwright默认安装。没有浏览器时明确记录未执行，不自动联网安装。

```bash
python validation/test_browser.py
```

实际执行环境限制URL导航，因此报告中的浏览器检查以内存加载精确HTML，真实origin持久化/直接打开/刷新未验证。不要把保存失败分支的通过改称“存档系统完成”。

## HTML在本地查看

`prototype/UI_Wireframe_v0.1.html`是单文件，无外部字体、脚本、音轨或网络请求。支持的浏览器可直接打开；文件origin存储受浏览器设置影响，失败时有明确提示与导出。也可在自己电脑仅绑定本机启动静态服务：

```bash
python -m http.server 8000 --bind 127.0.0.1 --directory prototype
```

然后在浏览器打开`http://127.0.0.1:8000/UI_Wireframe_v0.1.html`。这是一种本地查看方式，本轮没有在受限浏览器中验证HTTP导航。不要将服务绑定公网或上传私人档案。

# 1. 任务、目标、事件不是同一种东西（QEV-01）

| 对象 | 精确定义 | 例子 |
|---|---|---|
| 叙事节点 | 一段必须发生的故事进展 | Q-102使撤离成立，并为事故调查提供后续入口 |
| 任务定义 | 可版本化的目标、条件、反馈、结算契约 | 《最后一班渡轮》的固定规则 |
| 任务实例 | 某个冒险世界中实际被接受和推进的一次任务 | 当前存档里的这艘民用渡轮撤离 |
| 目标节点 | 一个可观察结果、当前条件或确认行为 | 支架安装、当前配置测试有效、方案确认 |
| 方法分支 | 达到同一个目标的不同操作路径 | 战斗、停机、潜入取得同一支架 |
| 内容事件 | 占用人物/场景或提供一段叙事交互的单元 | 邀请玩家接委托、离港表现、收到回信 |
| 系统消息 | 模块间描述已经发生事情的通知 | `物品转移已提交`，不是一段剧情 |
| 行动回执 | 世界已经接受某次动作的权威记录 | 此实例的渡轮已经离港并完成单次结算 |
| 学习观察 | 对材料、帮助和表达的记录 | 这次借助字幕完成理解，写作尚未评估 |

后文的“事件”默认指内容事件，不指底层消息总线。Codex不能把二者都写成一个没有来源权限的字符串触发器。

本版把第二部分的32个叙事节点映射为32个**顶层主线任务容器**，保持Q编号不变。这是本部分的新实现组织决定，不表示全游戏只有32项工作，也不意味着每个容器时长相等。容器内部的目标、护送分段和六塔工作单不膨胀计算为新的主线叙事数量。

## 1.1 本系统承担与不承担什么

本系统判断：任务何时可接受；已有行动如何计入；哪些条件当前有效；哪个事件能出现；玩家确认后提交什么结果；如何恢复和结算。

本系统不判断：玩家是否达到C1；句法评分的精确数值；某个技能的伤害；某扇门的实际碰撞形状；哪一套模型供应商最好。相关系统提供受控结果，本系统不能越权补造。

**关闭任务不等于关闭学习；播放剧情不等于世界已提交；NPC说“完成了”不等于真实条件已经成立。**

# 2. 玩家层面的任务体验（QEV-02）

任务来自遇见人物、检查现场、收到通信和承担工作，而不是地图上无限闪烁的问号。提供目标、受影响对象、已知限制和可能的下一步；不提前写出需要推理的答案。

默认HUD跟踪一个主要任务，另有最多两个相关小目标；任务日志可以容纳全部已接受内容。该显示数量为初值，不是接受任务上限，不设置“先放弃主线才能接支线”。

任务卡至少显示：为什么做、当前已确认进展、未完成的实际条件、可以联系谁/调查哪里、保留草稿入口。历史里保存已经执行的选择和结果；世界事实、NPC说法、玩家笔记分栏，不混写。

## 2.1 接受与承诺

明确接受需要实际投入或有剧情后果的委托。救援开场可在玩家选择开始冒险后自然激活；检查一个物品可以提供任务提议，但不能自动承诺替别人花钱、公开身份或发船。

同一任务的多个接受入口指向同一个实例。广场联系人和哈文不能各生成一艘需要修理的渡轮。

接受一般任务不立即锁定全部NPC和资源。具体运输、借用和支出在相应行动提交时再作承诺。任务接受本身也不授予虚假的知识掌握。

## 2.2 退后一步不等于失败

“稍后再说”只是暂时关闭提议；“取消跟踪”只改变HUD；“暂停这项工作”保留实际进展。三者不撤销已完成的修复，不刷新奖励，不删除草稿。

只有明确提出“放弃已承诺工作”时才走撤回流程，说明实际影响，返还未使用的借用品与资源，保存已经发生的事实。主线不允许因普通放弃操作永久锁死；它转为暂停或提供预设替代沟通。

# 3. 任务生命周期：三个持久状态，若干派生显示（QEV-03）

避免把“可交付、等回信、暂停、评估中、播放结算动画”都写成互相冲突的任务主状态。

| 持久生命周期 | 含义 | 允许变化 |
|---|---|---|
| `unaccepted` 未接受 | 实例尚未承担；可能隐藏、被听说或已提议 | 显式接受后进入active；真正永久拒绝的可选委托进入closed并记录原因 |
| `active` 进行中 | 承诺存在，实际工作可以继续 | 在受控结算/撤回/替代中进入closed；暂停不另建实例 |
| `closed` 已关闭 | 本次工作的结果已正式记账 | 普通操作不重开；新事件用新实例；读早期存档恢复其原世界 |

`closed.outcome`区分`completed`、`completed_with_consequence`、`withdrawn`、`declined_permanently`、`superseded`。主线正常语言/战斗失败不能写成永久失败结果。

## 3.1 派生显示

未接受时，由当前世界条件与认知决定“未出现、听说过、可接受、暂不能接受”。这些是视图，不覆写已经发生的剧情。

进行中时，显示“处理中、条件已齐、等待已声明依赖”。暂停/取消跟踪是独立偏好；等待回执必须有具名工作单、可解释缺项和主动推进入口，不能无限等待不可见后台。

**`ready`可随世界条件改变而回到`working`。** 灯通过测试后拔掉电池，当前状态失去就绪，但历史测试记录仍在。`closed`不会因为NPC走开就自行回退。

`committing`可以是短暂内部操作状态，不是允许存档永久停留的任务阶段。持久化最终只能恢复为提交前或提交后的完整稳定状态。

## 3.2 三种关闭不是“失败分数”

完成但有后果：玩家确认在安全底线以上采用不同资源安排，记录相应世界后果。

撤回：可选工作被明确取消，已执行部分保留，未使用预留释放；不会把已发出的私人信件当作未发送。

被替代：剧情阶段或另一项兼容工作已经合法解决问题，旧容器指向新的回执。不能再发一份同一工作的奖励，也不能隐藏取消理由。

# 4. 目标怎么组成任务（QEV-04）

## 4.1 八类目标语义

| 类型 | 判断对象 | 是否持续有效 |
|---|---|---|
| 历史回执 | 某个合法动作确实发生过 | 在当前冒险历史里保持；回档按对应分支恢复 |
| 当前条件 | 当前设备、物品、供给是否满足 | 随世界变化重新判断 |
| 带版本的检验证明 | 哪个配置在什么规则下测试通过 | 配置或规则不一致就不再证明当前可用 |
| 已确认方案 | 玩家确认过哪个版本的意图 | 修改正文/提案后需重新确认 |
| 已提交选择 | 公开范围、资源方案或处置方式 | 提交后成为历史事实，不由评价改写 |
| 汇总目标 | 所需独立工作是否全部满足 | 按每项实际回执与当前资格计算 |
| 可选发现 | 额外工单、人物线索、一般奖励 | 不进入主线必需条件 |
| 提交结果 | 最终动作正式发生 | 是输出，不能又作为自身提交的前置 |

拿到支架是历史；支架当前是否装在灯上是现状；当前灯有没有经过对应测试是证书。不能只用`bracket_done=true`或`beacon_tested=true`把三者覆盖。

## 4.2 并行、替代和可选

`all`表示所有实质条件都需要；`any`表示任一等效方法可成立；`exactly_one`仅用于玩家必须确认一种互斥政策，不用于禁止玩家调查过多条路线；`optional`不进入结算门槛。

三种工坊方法汇合到“支架合法取得”，不要求同时战斗、停机和潜入。玩家先试潜入后决定战斗，只记录真实方法过程，不额外发三份结算。

## 4.3 接任务前的合法进展

接受时和每次相关状态变动后，都从世界权威状态和合法行动回执重建目标视图。不能只监听“接任务之后第一次拾取”。

已有支架直接计入；已经安装的支架不要求拆下重新放入背包；已经取得的录音仍可使用。匹配实例、对象、材料版本和来源权限，不能把另一艘船或另一份练习的动作算进来。

重新扫描事实只是更新视图，**不重新消费物品、签发许可或发奖**。

## 4.4 条件依赖与信息揭示分开

关卡内部知道正确航道，任务日志不能因此提前显示。默认目标是“确定可行路线”；玩家检查设备后可显示“支架损坏”；只有已确认的提案才成为“你准备采用的方案”。

证明责任的任务需要可核验来源与玩家确认的主张，不要求点开所有文献，但也不能凭自由输入“我知道是谁”凭空创建证据。取得原始文书是实际调查条件，阅读几秒钟不是。

## 4.5 未知不是肯定，也不是已否定

条件查询可返回成立、不成立、未知。缺少关键配置、授权或材料时，未知不能通过`not`变成成立。向玩家给出已知范围内的处理方向；缺陷或数据不兼容走明确恢复，不伪造“世界中从来没有这份资料”。

任务定义中未注册的字段、任意脚本表达式和自由文本命令一律不能被执行。

# 5. 全主线依赖与并行安排（QEV-05）

宏观章节顺序不变；章内允许先调查、并行准备和提前合法取得材料。`activation_after`表示正式承担这一容器的前置；`additional_close_after`表示可以先做，但正式结算还等待另一项实际工作。场景访问与合法调查不因顶层容器未激活而全部封锁。

例如Q-103在取得委托后可以登记工单、开始初步调查；最终取得并核对撤离后的记录需要Q-102结果。不能因为玩家先看了工单就提前确认全部事故责任。

苔林的名单核查与转供站检修并行；矿区的签章调查可以与救援交错，但最终核对所需现场信息在救援进展中取得；学城的数据比较与失败试验复原并行，正式试验等待两者的实际条件。

## 5.1 第六章的关键依赖

```text
Q-601取得当前测站依据
  ├─ Q-602开启：逐地区登记、补齐基础回执；可同时开展增强工作
  └─ Q-603开启：本地货载与运输准备 → 分段护送 → 风脊塔回执
                                          ↓
                          Q-602汇总到第六塔回执后可以关闭
                                          ↓
                          Q-604展示资格、处理缺项并确认起航
```

Q-603只等待本地运输所需条件，不等待Q-602全部完成。Q-602可以等待Q-603产出的第六塔回执。这是单向依赖，不构成互相等待。

增强准备不是Q-602的强制关闭条件。不准备分布式方案的玩家也可完成全部基础主线。

32个容器的完整登记见文末附录A与配套JSON。依赖无环仅证明顶层组织关系；不证明全部任务内部机关、资源和NPC过程已经可达。

# 6. 每项任务的制作契约（QEV-06）

| 字段组 | 必须写清的内容 |
|---|---|
| 身份与版本 | 定义ID、版本、世界实例、是否一次性、相关叙事节点 |
| 入口与动机 | 出现条件、接受入口、委托对象、实际需求 |
| 场景引用 | 现有场景、热点、合法提交位置、离开后的替代入口 |
| 世界条件 | 前置、当前限制、权限与所依赖的数据持有方 |
| 目标图 | 必需/可选目标、并行关系、汇合点、信息揭示条件 |
| 内容包 | 文本、录音、图表、来源、版本和访问范围 |
| 方法 | 可行操作路径、战斗或机关结果的受控接口 |
| 沟通 | 默认自由写作、受控语义确认、澄清与离线办法 |
| 后果 | 玩家确认的选择、实际写入域、重要变化的前置预览 |
| 失败与暂停 | 重试范围、撤回效果、局部恢复与出路 |
| 资源 | 借用、预留、运输、消耗和归属；不能只有一个笼统扣钱字段 |
| 结算 | 单次回执、奖励类别、背包满时的投递处置 |
| 事件占用 | 人物、前景插槽、物件、可打断点与替代站位 |
| 阶段窗口 | 能否延后、何种明确阶段使任务变化、提前警告方式 |
| 学习观察 | 材料与目标别名、实际帮助、输入方式、提交版本；不直接造分数 |
| 验收 | 正常路径、替代路径、乱序、错误、重复、存档与不可达检查 |

本部分提供语义，正式JSON Schema、组件/类名与消息格式由第十二部分确定。临时原型可采用配套参考模型，但不能声称它已经覆盖正式契约的全部字段。

# 7. 方案确认与世界执行（QEV-07）

玩家可以提前起草条件式计划，例如“修好灯后经C离港”。草稿可以比实际装置准备更早完成。

流程分为：**草稿 → 可澄清的意图提案 → 玩家确认意图 → 检查实际准备 → 预览并确认执行 → 世界提交**。

## 7.1 三种判定不能合并

语言模块可说明表达是否准确；受控规则判断方案是否符合世界事实；最终执行由玩家明确确认。语言服务返回“很好”不能发船，错误冠词也不能让可行方案自动失效。

默认提供真实自由输入，模板和结构化确认是可见的帮助/离线通路。空白文本不能记为完成独立写作；玩家选择辅助整理后仍可推动世界，学习记录诚实标记。

## 7.2 两种版本失效

**提案正文或意图版本改变：**旧确认不再对应现在的文字，重新确认；旧稿仍作为历史保留。

**设备配置改变：**旧测试不再证明当前配置。即使先拔电池又插回相同位置，也要重新测试，不能只比较外观布尔值。

提早确认的条件式意图不因正常修复自动变成错误；它仍可使用，但正式执行前必须针对当前设备再预览。不要每安装一个零件就强制玩家重写全文。

## 7.3 执行预览只绑定有关条件

绑定任务实例、内容规则版本、许可版本、设备配置及测试版本、当前提案及确认版本、船只阶段与当前加载上下文。更换场景/关闭确认界面/读取存档后旧的未执行确认失效。

查词、读取材料、到达一条无关来信或收到语言反馈，不应使有效准备反复失效。不要用“整个世界任何字段改一次都要求重确认”的粗粒度版本号。

无现实时间过期：不因为玩家在确认界面读得慢而取消操作。若相关事实真的改变，重新展示差异和可处理方向，不自动替玩家选择新方案。

# 8. Q-102完整任务定义（QEV-08）

## 8.1 身份、接受与结束

任务名：《最后一班渡轮》。沿用六个场景R1-S02至R1-S07，使用第三部分同一渡轮、支架、工坊与电池实例。

完整版在Q-101签发临时检修委托后可接受；联系人和哈文工作台是等价入口。样章从同等世界许可开始，只跳过Q-101的演示过程，不虚构玩家读听写成绩。

结束是**民用渡轮撤离，玩家继续留港**。微光号使用权由Q-104移交。本任务不能同时偷跑第二章旅行与塔站首领结算。

## 8.2 事实与材料绑定

| 材料别名 | 既有场景热点 | 固定内容 |
|---|---|---|
| MAT-R1-A-C | R1-S02.bulletin | A关闭；C开放但需要工作导航灯 |
| MAT-R1-CORRECTION | R1-S03.dispatch_audio | 更正损坏部位、工坊支架位置、主发电机限制 |
| MAT-R1-B-LIMIT | R1-S03.route_b_rule | B需辅助泵运行，最大吃水1.2米 |
| MAT-R1-VESSEL | R1-S04.vessel_spec | 本渡轮规定载况下吃水1.4米 |
| MAT-R1-LOCAL-MODE | R1-S07.maintenance_note | 独立工坊储备、固定测试灯架与侧道条件 |
| MAT-R1-GENERATOR | R1-S07.main_generator_tag | 主发电机隔离未完成，当前不可启动 |
| MAT-R1-UNVERIFIED-ORDER | R1-S06.work_order | 后续调查工单，尚不能单独确认事故责任 |

MAT编号是本部分新增的制作别名，不假装已存在最终英文文件。英文终稿、音频与具体语言标签由第五、六部分制作；场景热点和固定事实沿用第三部分。

固定航道解仍然是取得支架、使用船内充足备用电池、验证灯后经C撤离。工坊备用供给不是船内电池；固定测试灯架不是导航灯；工坊机械不是Q-104塔站机械。

## 8.3 目标表

| 目标ID | 内部目标 | 满足依据 | 是否参与离港门槛 |
|---|---|---|---|
| O-102-PART | 取得替换支架 | 合法取得的历史回执；已经安装也有同一来源链 | 过程里程碑；不要求再次持有 |
| O-102-FIX | 完成物理修复与供给 | 支架已安装，电池连接且有规定储备 | 是，当前条件 |
| O-102-TEST | 验证当前配置 | 通过记录对应当前设备配置版本 | 是，带版本证书 |
| O-102-PLAN | 说明并确认可行安排 | 合规命题与玩家当前版本确认 | 是，不读语言分数 |
| O-102-DEPART | 撤离已执行 | 离港提交回执 | 这是结果，不作自身前置 |
| O-102-WORKORDER | 保存待核验工单 | 材料访问回执 | 否，后续调查线索 |

O-102-FIX、TEST、PLAN全部成立，加上合法委托、任务进行中和船尚停泊，才派生为“可以确认执行”。这不是“凑够三项进度”规则，每项有具体物理或沟通含义。

初始目标不展示内部答案表。检查后才显示支架损坏；玩家提出C后才显示其计划。正常日志不能泄漏未来叙事。

## 8.4 命题检查，不是标准答案匹配

有效提案表达：采用C；A因关闭不适用；B因本船吃水超限不适用；替换支架并用充足备用电池；主发电机在确认安全隔离前保持关闭；检查导航灯后离港。

允许短句、复句、条件式安排和不同同义表达。机器可用的命题对象只是对意思的投影，不能用“包含C、battery、off三个词”冒充理解。

玩家遗漏关键信息时由负责人提出针对性澄清；系统无法可靠理解时提供显式结构化确认。后者通过世界检查，不标为独立完成写作。

## 8.5 方法分支

正面路线：玩家确认遭遇，受控战斗结果让该维护机械停用，取得同一支架。

停机路线：在检查间识别对象，隔离工坊独立装置，侧道进入。错误操作可修改，不扣唯一船内电池。

潜入路线：启动固定检查，机械保持注意，走安全侧道。无现实倒计时，不以看文献耗时取消模式。穿过正面扫描区的风险双向存在。

方法可以中途改选，实际状态保留；不可为同一工作按完成的方法数量重复结算。

| 动作 | 实际前置 | 成功写入 | 不成立时如何处理 |

| 接受撤离委托 | 已有合法临时检修委托，未正式接受 | 当前任务实例active | 指向Q-101或现有接受入口；不查英语成绩 |

## 9.1 允许的顺序

可以先看船、先听录音、先调查工坊；可以先拿支架再接受撤离委托，前提是Q-101权限确实存在；可以先连接电池再安装支架；可以很早就开始写草稿。

不可绕过实际可达条件在无权限时隔墙拿物；也不可把“先装再接”误写成唯一可行顺序。

## 9.2 具体错误及合适反馈

| 玩家情境 | 应给的信息 | 不应发生的事 |
|---|---|---|
| 选择B并启动辅助泵 | 泵的条件之外还存在船型限制，可回看现行资料 | 自动沉船；把B改成正确答案 |
| 支架安装但没接电 | 当前装置没有合格供电 | 扣除语言分数并重置工坊 |
| 测试后拔掉再接电池 | 当前配置尚未重测，保留旧记录 | 旧true标记继续放行 |
| 说明中否定含义不清 | 展示理解到的行动，要求确认 | AI自行选择发船或公开身份 |
| 表达清楚但语法不完善 | 接受行动意图，语言问题进入反馈 | 随机扣基本奖励 |
| 使用完整解法 | 世界照常检查，学习标记帮助 | 字典使用导致坏结局 |
| 多次提交相同命令 | 返回同一回执 | 多发经验或重复卸掉装置 |

样章的世界规则不以材料打开数量为前置，也不以“播放到最后一秒”代表听懂。正确信息可以由不同合法路线取得；学习系统另外判断证据质量。

# 10. 离港提交、通知与回档（QEV-10）

## 10.1 一次不可分割的世界提交

一次离港必须共同完成：任务关闭与离港回执；船只离港及舷梯关闭；主角与协作角色移到R1-S02登记安全点；船上已装设备继续归该民用渡轮；相应基本奖励结算资格；保留材料访问；登记可补播/跳过的表现。

不自动修复主发电机，不移交微光号，不关闭Q-104，不把工单升级为已确认的事故责任。

## 10.2 世界提交先于可跳过的表现

确认后先形成完整稳定的世界结果，再播放船离开与人物反应。动画是结果的表现，不是唯一结算代码。

恢复时若回执存在，可从合适的表现点继续或跳过；不能重新发船、再次扣物或再发奖。若回执不存在，恢复仍停泊的完整状态。

Q-103的后续记录来自调度室/保管间/负责人，不依赖已离港的船。任务可以在当前结果提交后开放一个“不抢输入”的后续入口，不强制立刻播放全部调查对白。

## 10.3 幂等与分支

命令携带唯一操作标识与内容摘要。同一命令重传且载荷一致，返回原回执；同一标识换了内容，拒绝冲突。语义上的同一任务结算槽还要有单次约束，不能换个命令ID就再发奖。

同一现实工作即使因撤回重接、替代委托而换了显示容器，也沿用同一个世界目标结算槽；不能靠新任务实例再次奖励已经完成的工作。可选委托重接需有明确规则，新实例承接原世界进展与未使用资源，而不是复制物品、复位NPC或抹去已发出的信件。

结算台账跟随冒险存档。读取提交前快照，那里没有该结算，可以正常完成一次；读取提交后快照，回执与奖励仍在，不能再领。

不能把全局学习历史当跨存档禁领奖名单。也不能每次加载就生成一个全新的任务实例、从而把已完成工作变成未完成。

加载时生成新的交互上下文，只用于拒绝未提交的旧点击/异步命令；它不清空持久的任务回执与奖励记录。

# 11. 普通支线样例：SC-R1-001《两份相同的订房》（QEV-11）

这是一项**本轮新增的地方支线方案**，使用第三部分R1-O01潮汐旅舍，不新增必需地图，也不改写主线历史。其内容不暗藏中央阴谋。

## 11.1 情境与固定边界

旅舍账本出现看似超订：同一订房编号BKG-17的旧确认与改期确认被记成两笔。另有一笔独立的BKG-22。当前需要安排的是两个实际到达的同行组，而不是三组。

制作用固定相对日期/当地日历的具体值，所有材料使用同一版日期。本轮确定的结构是“旧日期经确认改为当前住宿日期”，不把人名相同或纸张相同自动视为同一客人。必须核对订房编号、修订关系与确认者。

两组当前要求分别为两张床且安静、单人且平层出入；可用房间分别满足这两个条件。房间属性通过公开房牌和现场查看取得，不需要进入新的房间地图。完整英文信件、改期录音与措辞在第五/六部分制作。

## 11.2 玩家实际过程

接受店主的核对请求；查看旧信与改期说明；听取住客确认；在近景中核对两间房的实际属性；修正账本，将两个有效订单分配到满足条件的房间；写一段确认留言。

语义目标是分清“记录副本”和“独立订单”，不是把所有材料标成已读。两份同来源副本不被误认为两项独立证据。

## 11.3 选择与后果

完成住宿基本安排后，可以选择店主预先同意的两种额外补偿形式，例如账内折让或提供本地信息服务。具体经济数值留第七部分；不能让主线必需物资成为强制赔偿来源。

结算改变旅舍住客站位、账本和后续闲谈，提供一次性地方奖励。没有关联主线结局资格的隐形道德分。

拒绝后主线正常；接受后暂停也不让住客按现实时间自动失去房间。章节推进可能改变交付方式，改为店主书面确认，须有预设兼容版本并保留承诺结果。

## 11.4 验收重点

先听录音再读旧信仍成立；两次打开同一确认不会新增订单；辅助写作后正常结算但不冒充独立表达；店主被同场前景事件占用时可稍后办理，不自动复制第二位店主。

# 12. 护送、战斗与局部失败（QEV-12）

## 12.1 Q-603按安全行程段推进

使用R6-S05物资中转棚、R6-S06风脊外线、R6-S07风脊塔机房。进入每个危险段前说明货载、随行人员、目的地、备用方案和不能折叠的旅行限制。

```text
本地货载与人员确认 → 装运 → 第一安全段 → 危险处置 → 下一安全段 → 到达交付 → 现场核验
```

不是让货车在玩家看文献时持续前进，也不是让独立NPC寻路失败成为任务失败。

## 12.2 重试作用域

失败恢复本段战前位置、货载和战斗资源；之前已交付的路段、已开通路、材料和草稿保留。一个路段的成功交付必须产生自己的回执，加载与动画重播不重复交付。

可在安全点中止并返回上一安全区；高风险段内不能用世界地图把货物直接瞬移到终点。UI要说明当前正在执行哪一项运输承诺，并提供结束/退回/安全托管方法。

## 12.3 失败分四类

操作失误：机关给可理解反馈，局部复位。

战斗失败：受控遭遇检查点恢复。

语言未理解或系统判不懂：澄清、支持、离线确认，不自动杀人。

已明确确认的风险选择：执行预设局部代价或不同结果，但不能取消主线全部恢复路径。代价由行动与世界条件产生，不从词数和模型评分随机换算。

重复错误不持续扣除通关唯一资源。没有补给时必须有基础恢复或低风险路线，不能依赖刷随机掉落脱困。

# 13. 六塔准备与可委托工作单（QEV-13）

## 13.1 不用一个“塔已完成”字段

每座塔分别记录：当前安全；基础本地保全；增强装置及其配置版本；过渡物资；实际值守人员；地方试运行许可；现场试运行与所用版本。全局另记录技术包验证和共同协议。

早期章节稳定塔站，不自动填满后期工作单；后期新增改造也不把旧安全工作重新标成失败。

第四章发布准备清单后可以开始安排增强工作。第六章统一核对，但不要求先完成Q-602才能做所有增强任务。

## 13.2 工作单不是随机跑腿

工作单唯一键为“本次准备包＋塔ID＋工作类型”。一般类型包括基础核验、增强安装、过渡供给、值守指派、现场试运行。同一项从地图、通信台和NPC处打开，必须是同一工作，不生成三份重复奖励。

技术包和共同协议属于全局工作，不能错误地要求玩家完成六份内容完全一样的技术发现。

物资和人员可以来自地区工程队，不依赖四名同伴全部招募。资源数据用带数量与单位的条目，不能用一句“物资充足”替代库存。具体经济数值由第七部分确定；原型使用显式有限测试库存，不使用不受约束的无限占位供给。

## 13.3 委托的六个步骤

| 阶段 | 必须存在的事实 |
|---|---|
| 拟定 | 明确塔、设备、任务范围、目标版本 |
| 资源核对 | 可用队伍、所需物料、合法航路和岗位容量都满足 |
| 确认派工 | 玩家知道将使用什么；全部预留一次成功或全部不发生 |
| 规定工作步骤 | 工程队依次取得交付、安装、核验结果，不能按日历空等 |
| 回执生成 | 来源、人员、配置、结果与未解决项可追查 |
| 接受工作结果 | 受控规则核验回执，更新对应准备项，不连带把全塔全部升级 |

“队伍已经答应”不是“工作已经完成”。“零件已经运到”不是“已经安装”。“已经安装”不等于“当前配置试运行通过”。

## 13.4 游戏内推进方式

派工在合法的生产/行程步骤中推进；打开菜单、反复读同一封信、睡眠现实几小时、重载存档不增加工作量。

玩家不做其他任务也不能永远收不到回执。通信台提供明确的“执行下一工作步骤/核对现场”入口；条件齐备时按受控规则完成该步骤，条件不足时显示具体缺项和取得路径。它是游戏动作，不是承诺现实世界过几小时返回结果。

委托遇到阻碍时，从固定事件或既有任务中提供处理方法，不随机撤销关键技术人员，也不把重新登录作为唯一修复。

## 13.5 资源归属与撤单

库存从仓库转为运输中、已交付或已安装；一个实物在同一时刻只有一个归属。已运走的零件不能又在仓库参与另一项预留。

取消未执行工作释放未使用预留；已经安装的装置保留，不能退款后继续算完成。两个工作单争用同一工程队时不能同时全额占用，其时间/岗位容量由显式工作步骤安排。

主线必需供给与可选补偿资源分池或作等价保障。支线不能先花掉主线唯一来源，导致只能重开游戏。增强准备必须有公开、有限可行的补齐路径，不靠无限刷题或随机商店刷新。

## 13.6 防止另一个循环依赖

现场试运行需要技术方案、当前安装、试验供给、合格人员和**地方试运行许可**。

六方**最终共同协议**可以参考试运行结果再确认。因此，不能要求“全部地方先签最终协议才能测试”，同时又要求“所有测试通过后才能签最终协议”。地方试验许可与共同运行协议是不同对象。

## 13.7 起航封存准备，不在终章偷偷变条件

Q-604列出可行结局方向、每类缺项和所有未了高风险承诺。玩家可继续准备、使用实际委托，或明确接受当前可行的两个基础方向。

最终起航需要六塔基础保全、边境现场任务完成和玩家确认；不强制完成所有可选支线。现场必须交付的进行中承诺要安全交接或明确暂缓，普通未接受支线不能阻塞起航。

确认起航时保留存档并封存准备清单/相关回执版本。进入终章后，不允许低优先级事件突然耗尽这些已经锁定的准备，导致公开显示可行的方案在最终按钮处无故失效。

中央危险程序是否稳定仍由Q-F03现场结果决定；起航清单不能替代终章处置。最终结局资格同时使用已保全的准备与真实现场稳定结果。

| 委托提议 | 让玩家知道可以承担什么 | 只创建/展示提议；接受由玩家触发 |
| 主线现场事件 | 救援、交接、装置操作、接管 | 只提交所注册的动作与结果 |
| 后果事件 | 离港、修复后生活、来信 | 读取正式回执；不再次结算原任务 |
| 同伴事件 | 个人交流、共同经历 | 改已声明关系/个人进度，不补造主线事实 |
| 地方支线 | 具体居民或机构问题 | 只改允许的地方结果域 |
| 工作回执 | 接收具名团队的实际结果 | 由工作单验证，不按NPC对白直接全满 |
| 复习事件 | 新情境中再次使用语言 | 不重置主线装置，不产生无限战力奖励 |
| 环境生活 | 小对话、声音、人物反应 | 不夺控制，不改变关键规则 |

候选匹配是查询，不是已经发生。候选满足世界与权限后，生成/恢复对应实例，状态为`queued`；安全地取得资源后成为`running`；在声明检查点可`paused`；完成为`completed`，合法撤回/替代为`cancelled`并记录原因。

未接受委托的提议可以留在队列，不占用全场人物。暂停事件保存情节检查点，但释放不需要持续占用的前景资源。重新进入时按同一实例和版本恢复，不重新抽一个相反内容。

## 14.1 事件至少声明

定义ID、版本、发生条件、唯一发生键、可用场景插槽、参与人物、允许读取的事实与知识、允许写入的结果域、显示优先级、打断策略、替代入口、结束与清理方法、重访/阶段处理、奖励引用和学习材料引用。

如果出现条件、角色知识或世界版本不成立，事件不能通过临时生成一句解释绕过事实。选用兼容变体、延后，或按明示理由不展示。

# 15. 前景调度、人物占用与不打断原则（QEV-15）

沿用第三部分：每场景最多一个主导前景事件；非阻塞装饰另计。单人玩家同一时刻也只有一个控制输入的前景会话。涉及的NPC在全世界层面只能有一个冲突中的实际占用。

## 15.1 先检查可打断边界，再比较优先级

写作、资料阅读、语言帮助、行动确认和战斗决策保护输入。任何新主线、支线或复习邀请都不能因为优先级高就强制关闭正文。

优先级用于**下一个安全调度点选择谁运行**：已经确认的动作收尾/安全恢复最高；当前主线依赖和玩家明确选择的相关任务次之；剧情回执与同伴事件、地方支线、学习推荐随后；装饰最后。

正在运行的低优先级对话可以到预设检查点结束或由玩家暂停，不能被突然从半句话中移走。确有紧急剧情使用玩家确认的阶段切换，不在读英语时偷偷倒计时。

## 15.2 原子取得全部占用

事件声明要占用的场景前景插槽、人物与关键物件。全部可用才一起取得；任何一项冲突就全部不拿，避免事件A占人等门、事件B占门等人。

这些短期占用与运输物资预留不同。前景资源用于防止人物/界面同时冲突；库存预留是世界物资承诺，各有权威持有方。

角色被剧情扣押、离港或未招募时，不能再被生活事件当可用NPC。派生装饰与当前场景投影必须服从相同事实。

## 15.3 冲突时的具体选择

| 情况 | 处理 |
|---|---|
| 哈文正在参与玩家的方案确认 | 新委托留在任务日志或下个安全点，不新造另一个哈文 |
| 支线想占唯一主线路口 | 改用预设站位或延后，不改变碰撞堵路 |
| 玩家已经在写信 | 新来信只做非打断提示，正文自动保存但不强制退出 |
| 可选事件长时间未运行 | 玩家可在日志主动选入安全队列，或转到通信入口 |
| 保存时有前景事件占用 | 保存事件检查点；恢复后按当前合法状态重新取得占用 |
| 事件异常退出 | 释放它的临时占用，不回滚无关已提交世界动作 |

优先级不能成为永久饿死支线的理由。有效期内被延后的已接受事件必须有可主动访问的入口，不能仅以“可能随机刷出来”作保证。

# 16. 大量事件、可重复内容与阶段窗口（QEV-16）

## 16.1 内容量与出现频率分开

可以存储大量任务定义，但同次到访只展示少量与当前地区、任务、人物和能力需要相关的候选。初值：任务日志推荐最多三项；非请求式复习邀请同一安全段最多一项；不每读一段文字就弹一次通知。

候选种子、已绑定材料和发生序号随存档保存。读档、开关地图或走进同一门不能反复重新抽稀有奖励。

前景刷新由有意义的阶段、工作回执、任务结果、首次安全到访或玩家明确请求触发。阅读秒数、按键次数和现实离线时间不作为紧迫性推进。

## 16.2 三种可重复性

一次性剧情只在同一冒险实例发生一次。

受约束的地方事件系列使用不同人物需求、材料与约束；新发生键不自动意味着新鲜学习材料，必须保留内容与变体家族标识。

练习可重做并提供反馈，但不反复发放主线经验和关键装备。新生成ID、换人名或重排选项不能被学习系统直接当作未见过的独立材料；第五部分负责更细的证据判定。

运行时自由生成事件不进入第一可玩样章。制作阶段AI批量草拟、受验证的事件池与固定种子足以支持本阶段测试。

## 16.3 任务时限用明确阶段，不用现实压力

| 窗口类型 | 本版规则 |
|---|---|
| 无时限 | 主线调查及多数生活委托可暂停与重访 |
| 阶段窗口 | 某场公开活动/人物位置会在明确阶段后改变；提前说明并保留兼容交付或撤回路径 |
| 危险行程 | 只在玩家明确进入的路段内发生危险，不按读写现实耗时推进 |
| 永久转折 | Q-604起航等明确确认并保留存档的变化 |

阶段转换前展示受影响的**已知任务**，不要为了提醒而泄露未发现的支线秘密。主线必要证据不放在会静默过期的支线里。

有后果的阶段变更可以改变未完成的可选工作；必须说明承诺如何被交接、暂停或关闭。不能一边承诺所有NPC无期限等待，一边在结尾暗算“你离开太久”。

# 17. 奖励、经济与单次结算（QEV-17）

| 奖励项 | 结算依据 | 本部分决定 |
|---|---|---|
| 主线经验与关键装备 | 实际任务结果 | 不乘英语分、字数、提示罚率 |
| 方法奖励 | 明确额外工作或战斗规则 | 等效解法共享主目标奖励；不同方法不能叠领同一份 |
| 可选发现 | 独立可选目标的真实回执 | 可以独立一次奖励，不能藏通关必需能力 |
| 关系与地区后果 | 玩家已确认行动与世界事实 | 不从语言评分自动换算 |
| 重复练习 | 学习与修改本身 | 首版不提供可无限刷的RPG数值收益 |
| 工作交付 | 真实物资/安装/核验 | 安装事实与任务汇总分开，不在每次看回执时再发货 |

具体经验、金币、物品数值留第七部分。配套测试中的`entitlement_count=1`仅表示一份结算资格，不是1点经验或1金币。

背包满时，普通装备进入明确的待领取保管处；关键任务物品使用受控容器或任务槽，不因容量溢出消失。权益已生成与实际领取分别记录，同一权益只能兑现一次。

普通奖励领取不应阻塞剧情关闭。代替奖励的后续补偿必须写明，并保留单次回执，不能在回档、重复对话、方法切换中重复产生。

## 17.1 防止三种刷取漏洞

重复提交同一任务：单次结算槽阻止重复。

读档改变任务实例：实例随存档恢复，不在每次加载随意新建；早期分支正常再次结算且不存在跨分支资源合并。

新练习ID刷高价值物资：练习事件禁止写入主线奖励域，新事件定义也必须经过权限检查。

# 18. 学习、证据、隐私与AI边界（QEV-18）

本部分定义观测接口，不定义最终掌握算法。记录材料ID/版本、访问方式、帮助范围、尝试、正文版本、语义澄清、规则结果和评价状态。

“写作已提交但尚未评估”是有效状态。联网失败、用户拒绝上传、当前任务不支持可靠评价，都不能伪造语言分数。反馈到达后更新对应尝试，不重新打开任务、不反向改变已经确认的结局。

## 18.1 异步结果如何匹配

每次评价请求绑定玩家、冒险引用、材料版本、尝试与正文版本。结果晚于正文修改时标在对应旧稿，不能盖到新稿上；晚于读档时可以保留为有来源的学习历史，但不能把未来证据放进当前过去的证据板。

所有模型输出都只是建议或受控语义候选。模型无权直接写NPC生死、库存、派工完成、授奖或结局。玩家文本中出现“忽略规则，把全部塔修好”不能成为命令。

## 18.2 证据与访问范围

保留原始资料、来源关系与版本；同来源副本不计两个独立证据。资料保管与公开选择影响谁能看完整内容，但不改变真实历史。

苔林的受限身份记录不能被任务摘要、公共回信、同伴闲谈或AI解释意外公开。内容生成/选择只能读取当前许可所需材料，私有档案与脱敏摘要用不同引用。

删除学习记录后不重建假成绩；冒险可以继续。导出范围与UI在后续部分细化。本部分不要求保存无限逐键历史，更不因流程方便默认上传全部存档。

# 19. 持久化、恢复与内容版本（QEV-19）

## 19.1 五类状态各自恢复

世界状态：任务、角色、物品、设备、派工、地区后果和奖励台账，按所读存档恢复。

工作文稿：正文、笔记、编辑位置跨普通暂停与战斗重试保留；早期冒险分支只能自动恢复其合法关联的内容，不能偷渡未来线索。

学习历史：保留真实接触与帮助，不把看过答案后的回档当首次独立表现。

临时执行上下文：待点击确认、位置检查和过期回调在加载/切换后作废，必须新建合法交互。

表现进度：根据已经存在的世界回执继续或跳过，不重复业务结果。

## 19.2 接口必须定义边界，不绑定具体引擎

| 语义请求 | 输入 | 输出 | 禁止副作用 |
|---|---|---|---|
| 查询可接受/当前目标 | 任务实例、世界与认知快照 | 可执行性及安全解释 | 查询不能发奖、推进剧情 |
| 接受任务 | 合法入口、玩家确认、版本 | 同一任务实例或解释 | 不复制委托、不给语言掌握 |
| 请求现场动作 | 受控动作、对象、位置/权限上下文 | 世界回执或未执行原因 | 不执行任意字符串 |
| 提交行动方案 | 当前正文/语义版本和确认 | 可解释提案状态 | 不直接执行设备或政策 |
| 预览/确认重大行动 | 有关事实版本和明确确认 | 单次结果与回执 | 不使用过期点击跨场景发船 |
| 派工/领取回执 | 有限资源、队伍、工作单、当前版本 | 全部预留或全部不发生；验证结果 | 不凭一句“完成”填满全塔 |
| 请求事件前景 | 场景、人物、插槽、当前保护状态 | 取得全部占用或留队列 | 不部分锁住世界资源 |
| 记录学习观察 | 材料、帮助、尝试、评价状态 | 对应学习记录 | 不直接改世界后果 |

## 19.3 版本保持

任务开始使用固定内容包。事实、音频、规则、设备说明和提示属于同一版本关系；更新不能让旧录音回答新谜底。

有已开放的任务与正在派送的工作时，保留旧版本或执行明示迁移。迁移要处理物品归属、配置证书、分支回执、草稿和新场景落点，不能只改任务编号。

## 19.4 与第三部分参考字段的细化

`beacon_tested`细化为测试证书与配置版本的派生结果，不保留另一个可独立修改的布尔真值。

`confirmed_plan`细化为提案、版本与玩家确认，而不是一个布尔开关。

`departure_complete`由任务提交回执派生；船只表现、舷梯和结算使用同一权威结果。

第三部分原文和JSON不被本轮覆盖；本轮提供迁移语义供第十二部分统一。

# 20. 任务日志、回顾与调试工具（QEV-20）

玩家任务日志展示目标与已知进展，不展示内部所有真值、未揭示角色身份或唯一解。

长时间回来时显示：上次确认做了什么、当前尚未完成什么、草稿在哪里、可联系谁。回顾取自该冒险世界实际状态，不直接调用完整剧情Bible总结未来。

## 20.1 提示分级

目标提醒不泄漏答案；来源定位指出可以比较哪些已有材料；关系提示解释应关注的限定；完整方案只有玩家明确请求后显示。语言释义与解谜提示仍分开。

任务条件不成立时给可理解原因；“配置版本不匹配”对玩家可显示为“连接已变更，需要重新检查导航灯”，不能直接抛数据库错误。

## 20.2 给制作与Codex的检查视图

开发模式显示任务实例/版本、当前谓词真值与来源、未满足依赖、目标可见条件、NPC/插槽占用者、物品归属、派工预留、当前测试证书、结算回执和最后一次拒绝原因。

提供只读状态检查与局部调试动作；关卡整体重置仅用于开发，不作为正式玩家失败恢复。

必须能回答：“为什么现在不能提交？由谁持有该事实？哪个动作能改变它？这个动作当前是否可达？”仅输出一个`false`不足以验收。

# 22. 验收案例（QEV-22）

# 23. 本轮实际检查与限制（QEV-23）

配套`validation/validate_design.py`运行49项自动检查：主线与场景引用、顶层依赖无环、材料热点绑定、Q-102当前/历史状态与版本、提前取件、方法完成、重复命令、回档逻辑、模拟提交失败、保护输入和排他占用等。

Q-102有限抽象穷举得到228个可达状态、1324条转换和4个终止状态。在明确列出的动作和固定供给假设下，未发现无法到达完成状态的可达状态。

这与第三部分的空间状态模型不是同一个模型，数字不能相加当成完整覆盖率。本模型省略真实位置与碰撞，仅把合法到达视为受上位空间契约保证的前置；它不实现自由英文理解、NPC全调度、完整战斗、所有资源消耗、网络或实际磁盘事务。

内存中“先构造完整新状态再发布”的测试不能证明真实断电时的存档原子性。49个测试函数也不等于上表40项产品验收全部完成；例如实际音频降级、UI焦点、护送存档、资源调度和完整支线仍需在引擎实现后验证。

可运行命令见README。报告记录测试实际输出，不把未实现模块一律标成通过。

## 本部分的最终原则

**任务是一组有来源、有依赖、可恢复并需要确认的世界工作，不是一串必须按固定顺序点完的按钮。**

地图提供实际操作；任务提供结果规则；事件提供人物与情境；学习系统记录玩家在其中如何理解和表达。四者通过受控回执连接，不互相冒充。

下一部分：第五部分《英语学习系统》，确定能力地图、材料规格、听读写任务、反馈、支持记录与复现安排。

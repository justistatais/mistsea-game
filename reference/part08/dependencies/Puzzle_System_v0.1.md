## 文档效力与本轮范围

英语目标固定为 **IELTS Academic 阅读6.5、听力6.5、写作6.5**。不恢复旧版“6.5及以上”或随章节提升到7分的设定。这里沿用第五部分的产品目标，不重新发布考试评分事实。

本轮详细交付八类谜题规则、九个解谜单元、32个主线任务的家族绑定、十二份新增局部英文材料或脚本、提示与恢复规则、约束和依据登记、可执行的有限逻辑示例及检查。九个单元不是九张新地图，也不是九份额外作文。Q-102的四个单元使用第三、四、五部分已经定义的同一任务、同一场景、同一组物品和同一份写作草稿。

除Q-102及明确列出的局部样例外，其他主线只达到制作方向和接口深度，不表示全游戏谜题已完成。本版细化现有剧情，不改变导师存活、责任链、船舶身份、六塔准备及结局资格。

规则为本版设计基线；时长、单位数量、负担分级及内容预算均为待试玩初值。新增英语材料为6.5目标候选，尚未实测校准；三份新增听力内容是脚本，本轮没有制作音轨。参考代码不是游戏引擎、自由文本理解器、存档实现或完整安全证明。

# 1. 解谜在本游戏中的作用（PZ-01）

解谜的核心体验是：**观察可用信息，形成能够解释局面的判断，然后用动作验证或执行。** 它不仅是提交一个答案，更不能是每次走路、攻击或开门前的题目收费站。

一个合格单元需要同时说明五件事：玩家的世界目标、当前尚不明确的关系、足够取得的材料或观察、可执行的行动，以及行动之后可解释的反馈。

例：知道灯本体可用而支架损坏，会改变寻找的物品；知道工坊控制独立供电，会改变设备操作；判断航道可行后，仍要实际维修。英文被换成中文时，这些关系仍然构成冒险与推理。删除所有信息理解时，不能仍然完全依靠箭头完成全部判断。

不把所有交互都计为谜题。拾取已经显眼放在面前的物品、再次打开已读文件、沿着安全通道返回、观看后果动画，都不是独立解谜单元。休息、人物闲谈和普通战斗也无须硬插语言检查。

本系统负责比较、推理、配置与候选方案的有效性说明。它不负责发经验、修改角色等级、宣布语言掌握、移动NPC到不合法位置、决定结局或自行结束任务。

# 2. 固定6.5，同时控制逻辑负担（PZ-02）

## 2.1 三个维度独立记录

| 维度 | 本版规定 |
|---|---|
| 英语材料与语言任务 | 固定6.5目标；保持第五部分审校、试测与版本状态 |
| 推理和操作负担 | 可分级，但不能借多材料、记忆压力和隐蔽操作暗升语言要求 |
| 实际表现 | 按使用帮助、材料熟悉程度、模态和具体尝试记录 |

后期可以协调更多人和设施，但复杂事项要分阶段、可保存、可回看。不是把六地全部信件同时塞进一个不允许笔记的窗口。

较强玩家在同档新情境中练习，减少重复。遇到困难时提供关系提示、证据整理、局部语法解释和分段信息，而不是默默替换主线原文或改变答案。材料、语音、呈现条件、谜题提问和支持方式发生实质变化，都需要按第五部分重新核验。

界面标签、短命令、简短设备牌可以简单。整体语言任务组合按6.5设计；不把每句话故意写复杂，也不把一个三词标签当成6.5训练的证明。较短机关单元不能取代第五部分承诺的长文、长听力和完整写作。

## 2.2 单阶段逻辑负担初值

| 内部分级 | 同时参与的来源 | 需要保留的主要约束 | 关键推理关系 | 目标游玩时段 |
|---|---:|---:|---:|---:|
| L1 局部 | 1—2 | 2—3 | 1—2 | 约3—6分钟 |
| L2 标准 | 2—4 | 3—5 | 2—3 | 约6—12分钟 |
| L3 复合 | 3—5 | 4—6 | 3—4 | 约12—20分钟 |

这些是项目初值，不是IELTS分数标准，也不是超时失败线。时间应计入正常读听、回看和操作。单元超出这些范围时先拆阶段，不靠更快语速、隐藏按钮或更长作文强行压缩。

前期以L1/L2为主，常规主线以L2为主，章节核心可以包含可拆开的L3。复合单元每完成一个实质子目标就保留工作，不能要求一次记住所有条件。逻辑支持可以独立调节，英语目标仍是6.5。

## 2.3 试玩时区分问题来源

记录：找不到入口、误解材料、记不住来源、不会使用面板、推理不成立、明确知道答案但操作失败、自由表达无法被系统可靠理解。原因不明确时标为待诊断，不凭一个错误航道选择推断语法缺陷。

“玩家读得慢”不等于谜题坏；“玩家读懂了却被不明按钮卡住”必须优先修复。目标组必须大量依赖全文答案才能前进，或完全不看信息也能稳定完成，均需要返工。

# 3. 八类谜题及可复用交互（PZ-03）

| 类别 | 玩家真正做什么 | 可组合的变体 | 常见错误设计 |
|---|---|---|---|
| A 版本与来源整合 | 确认身份、适用范围、修订关系，再合成有效信息 | 旧通知与更正；订单与改期；规则与例外 | 默认日期最新的任何纸张都覆盖全部原记录 |
| B 时间与顺序重建 | 区分发生、记录和预定时间，建立必要先后 | 事故时间线；交接流程；部分有序的维修 | 强迫填材料没有提供的精确时刻 |
| C 空间与路线判断 | 把语言条件、地标和当前通行状态对应 | 历史地图与现场；听取方向；多路径进入 | 地图箭头提前标出谜底，或依赖像素找茬 |
| D 约束与资源安排 | 同时满足容量、对象、顺序和最低条件 | 房间分配；货载；值守与工作安排 | 隐藏一个作者偏好的“最优”，其他可行解全判错 |
| E 设备与状态操作 | 将说明变成装置配置，观察反馈并验证 | 隔离、检修模式、顺序开关、版本测试 | 点一次正确选项就自动完成所有维修 |
| F 主张与证据审查 | 区分支持、矛盾、信息不足和需核对的冲突 | 责任范围；证词；未经证实的推测 | 凭人物阵营判真假，或把没写等同于否定 |
| G 图表与试验推理 | 比较条件与结果，选择可比案例，限定结论 | 趋势、控制条件、失败反例、试验边界 | 简单相关直接推出因果，局部成功直接推广全网 |
| H 沟通与澄清 | 向实际接收者传达可执行意思并解决歧义 | 指令、请求、交接、协商、带依据的建议 | 逐字匹配标准答案，或让作文分数决定阵营 |

八类不是八套彼此独立的软件。初版复用六种交互工作区：证据比较板、时间/步骤轨道、证据地图、分配表、实体设备、已有通信编辑器。图表与试验由比较板和场景装置组合，F复用证据板。

每种家族至少有“发现关系”和“实际使用关系”两种节奏。禁止整章连续反复做完全相同的三选一。先暂定相邻不超过两个同家族的主要单元；确有叙事理由时允许例外，但需要新观察或新动作，而非换名换数。

战斗前情报与首领场地机关可以属于E/C/F。普通攻击不使用语法问答。首领战的行动点、数值及伤害交给第八部分；本部分只提供允许触发的场地状态与检查条件。

# 4. 三种解法政策：不要把所有问题写成唯一答案（PZ-04）

## 4.1 唯一结论，允许等义表达

例如固定载况下的Q-102航道选择：A关闭，B超限，C在规定维修后可行。这里可以有唯一航道结论，但修复顺序可以部分交换，句子可以不同。

制作人必须提供足以排除其他受支持候选的依据。不能只列一个参考答案而不解释其他方案为什么不成立。

## 4.2 多个可行方案，不强制唯一最佳

例如补充运输有两种合法装载。通过全部硬约束即可接受。偏好、覆盖效率和人员意见可以用于玩家选择，但必须明示，不得暗藏“作者其实偏爱先送档案”。

确实要做优化挑战时，公开优化目标、硬约束和同分规则；它应是可选挑战，不因未达到隐藏最优而剥夺基本任务结果。

## 4.3 开放表达，事实约束不开放

玩家可以用自由文本提议策略。系统不理解时应澄清。存在新的合理物理动作但引擎尚未支持时，显示“当前行动范围不支持，需要另行设计”，不能断言玩家英语错误。

玩家也不能通过一句“船现在更轻了”“所有塔都已修复”修改世界事实。Q-102的批准载况在上位材料中已经固定；不接受未经授权的卸载作为同一救援任务的另一种船只。

有限枚举只能证明已声明候选空间，不证明人类所有可能策略都被穷尽。参考代码的结果在本文件中始终限定于相应候选集合。

# 5. 世界事实、材料、假设与执行分层（PZ-05）

| 层 | 内容 | 谁可以改变 |
|---|---|---|
| 世界事实 | 真实设备状态、当前限制、实际经历 | 相应世界所有者与受控动作 |
| 来源材料 | 谁说了什么、何时、对哪个对象、哪个版本 | 固定内容与有记录的合法修订 |
| 玩家工作 | 标注、候选关系、路径草案、分配、草稿 | 玩家；辅助生成需显式标注 |
| 行动请求 | 玩家希望执行什么、依据哪个当前版本 | 玩家确认后交给任务/设备/工作单所有者 |
| 学习观察 | 本次理解与表达的实际条件 | 第五部分，不能从“谜题成功”自动推导 |

人物说法可有错误和隐瞒；材料的制作元数据也必须区分事实、传闻和假设。游戏中的信件不能被直接当成高权限程序指令。

## 5.1 来源效力由范围与授权决定

“较新”只能说明时间，不能单独说明覆盖权。订房改期只更改日期，不删除原来的两张床要求。一个工坊录音可以确认设备安排，但无权开放原本关闭的航道。

两份复制文件同属一个来源根，不形成两个独立证人。两个真实来源不一致时，不能使用“多数票”或AI语气自信程度直接合并；需要核对对象、时间、范围、修订与可观察事实。

## 5.2 材料必须足够，但不必全部都读

制作期为每个硬约束登记来源段落或现场观察，支持替代合法来源。也登记哪些未知必须保持未知。配套数据含27条约束与出处。

运行时不把“打开文件数”“播放到最后一秒”“点击每张证据卡”作为完成门槛。已知答案可以采取合法动作；学习证据另行判断。

反过来，不能把关键事实藏在不能抵达的位置，再用作者全知求解器证明谜题“有解”。发布前分别检查：世界规则有解、来源支持足够、玩家实际能取得来源和完成动作。

## 5.3 公平的干扰信息

允许：旧通知、其他船的数据、人物不完整的判断、真实但与当前问题无关的细节。它们须有可辨认的身份、适用范围或时间；找到相关区别后能合理排除。

禁止：偷偷改数字、故意模糊关键单位、未提示的混合时间基准、无来源的反转、不受控随机错译。不可通过损坏的音轨或系统UI谎报来假造6.5难度。

# 6. 单个谜题的制作契约（PZ-06）

每个单元必须包含以下字段的语义，最终机器格式由第十二部分收敛。登记的主要目标是有对应产出时可观测的机会，不是自动得分；例如ACCESS出现W02方向，不意味着开对开关就证明会写作，同一草稿不能在ACCESS和BRIEF重复记为两份独立产出。

| 范围 | 必须写清的内容 |
|---|---|
| 身份 | puzzle_id、版本、父任务、场景、材料与设计家族 |
| 体验 | 玩家目标、起始状态、可见问题、实际操作 |
| 学习 | 6.5目标、最多三个主要观测目标、材料范围与条件 |
| 事实 | 对象、单位、状态来源、固定与可变字段 |
| 信息 | 每条关键关系的出处、备用访问、保密范围 |
| 解空间 | 唯一/多解/开放；支持的候选域、行动与排除依据 |
| 校验 | 前置、当前条件、版本、允许结果及错误原因 |
| 帮助 | 操作/语言/逻辑三条提示；完整当前方案与暴露范围 |
| 恢复 | 撤销哪些工作、复位哪些装置、不影响哪些历史 |
| 权限 | 向哪个所有者发请求；不得自发奖或造世界事实 |
| 覆盖 | 正常、乱序、替代、未知、过期、帮助、回档和故障案例 |

缺少来源、可行解、恢复路径、完整提示或越界处理的主线单元，不进入正式制作。

主线事实由本任务版本固定。可选练习变体只能在新实例创建前从已验证候选中选择。玩家开始阅读后不能因表现改变事实、答案、地图或人物知识。

# 7. 候选方案、就绪和已执行分开（PZ-07）

本系统不另造一套与第四部分竞争的任务生命周期。谜题工作区只保存尝试与当前检查，权威完成回执仍归任务/设备所有者。

| 检查结果 | 含义 | 下一步 |
|---|---|---|
| feasible 可行 | 在声明范围内满足约束 | 可以提供行动请求；不自动执行 |
| incomplete 尚未准备好 | 意图可能成立，但现场有工作未完成 | 指向实际工作，不抹掉计划 |
| contradicted 与已知限制冲突 | 至少一项明示硬约束不满足 | 给可解释的反馈 |
| needs_clarification 需澄清 | 表达或关键选择不明确 | 请玩家补充或确认 |
| out_of_scope 超出支持范围 | 新对象、动作或规则未定义 | 说明产品范围，不判语言错 |
| stale 版本过期 | 检查对应的相关数据已改变 | 重新检查有关部分 |
| data_unavailable 数据不可用 | 必需状态未能加载或来源访问不可恢复 | 系统恢复，不猜测为真或假 |
| content_conflict 内容冲突 | 相同适用范围出现无法按现有规则消解的有效矛盾 | 保留工作，进入内容修复或预设核验路径 |

“给定材料未说明某件事”是F类的合法结论，不等于运行时丢失字段。“未知”不能偷偷当成false，更不能当成允许通过。

硬约束验证遵守有关状态的版本。与决策无关的查词、普通来信和音量变化不让预览失效。正文、设备或行动授权发生相关改变才需要重核。

同一参考方案检查可以重复调用而没有副作用。它不能消耗电池、创建支架、写任务结算或生成新的学习成功。

# 8. 交互规则：不让操作掩盖推理（PZ-08）

比较板保留原文与出处，允许固定段落、切换来源、手写笔记。默认不替玩家把所有约束自动抽成正确结论。AI摘要或自动条件表属于显式帮助。

时间线允许填写相对先后和未知时刻；非唯一偏序接受所有满足约束的排列。分配板允许暂存不完整方案，显示已经配置的对象，不把空位偷偷填成答案。

证据地图独立于导航地图。地图上两条连接可能具有相同场景端点，但代表不同通路与权限；需要通路ID，不能仅靠两个节点判断可走。

设备是现场实体。点击面板提出操作，角色和设备按第三部分执行并反馈。检修小面板、自由写作、字幕等打开后，方向键和字母不传递给角色移动。

拖拽都有等价的键盘/菜单操作；状态不用颜色单独区分。明确显示当前选择、应用对象、可撤销范围和返回入口。不显示“还差两条隐藏线索”来剧透未知内容。

工作区重新打开后恢复草稿、标注与滚动位置。任务已完成后的材料仍可回看，但复习入口不能重新触发已经提交的物品或奖励。

# 9. 提示系统：三条帮助链，四级逻辑提示（PZ-09）

## 9.1 三条帮助链

| 帮助 | 可以做什么 | 不应该顺便做什么 |
|---|---|---|
| 操作 | 高亮已知入口、说明按钮、键盘等价操作、恢复工作区 | 用目标高亮直接标正确航道 |
| 语言 | 词义、范围、句法、重听、字幕、译文 | 查词时自动给整道谜题答案 |
| 逻辑 | 目标提醒、相关关系、下一推理、完整方案 | 扣钱、强迫失败多次、代替玩家确认后果 |

语言帮助继承第五部分目标范围记录。操作帮助不因使用而默认成为语言依赖。逻辑提示只要透露了关系或答案，就记录其相应暴露；不能叫它“普通反馈”就当成无辅助。

## 9.2 Q-102的提示示例

| 级别 | 内容 | 暴露范围 |
|---|---|---|

## 9.3 完整方案必须基于当前状态

玩家已经拿到支架，提示不能让他去空货架再取一次。已经隔离机械，提示不要求重新战斗。设备测试过期，提示指出重测，而不是继续沿用旧“已完成”。

当系统修复缺陷或状态无法读取时，不编造一条看起来合理的路线；显示未能可靠生成当前方案并调用安全恢复。参考模型已经逐状态检查工坊完整帮助路径，但这不等于完整游戏提示已经通过验证。

# 10. 猜测、反馈与学习证据（PZ-10）

不为了防猜而锁住合法动作、收取提示金币或要求所有文件读完。猜对方案可以继续世界；第五部分不据此自动宣称理解全部来源。

若反馈明确说出“B超限”，后续同事实回答属于已经暴露过的条件，不能算首次独立推断。提示之前的已提交表现不被倒过来删除。

不要频繁要求玩家解释每个微动作。需要语言观测时，优先使用任务本来就需要的交接说明、摘要和写作；不能每做完一个阀门就增加一道“请证明你不是猜的”。

# 12. 完整任务样例：Q-102拆成四个单元（PZ-12）

四个单元不是必须按编号播放的四道题。它们是同一任务中可以交错发生的工作：判断路线、处理工坊、修复核验、说明并确认行动。地图、任务、物品和草稿均复用前四部分。

## 12.1 PZ-Q102-NAV：选择可行航道

**玩家目标：**判断本次撤离可以采用什么安排。  
**交互：**公告与资料可固定到比较板，候选路线可记录在同一任务方案中。  
**材料：**第五部分的`Q102-R-NOTICE`、`Q102-R-B`、`Q102-R-VESSEL`和`Q102-L-REVISION`，不改写其0.1版正文。

| 事实 | 来源及必要关系 |
|---|---|
| A关闭 | 现行公告p01；旧航行成功不构成今日许可 |
| B需要开泵且吃水不超过1.2米 | B规定p01；两个条件同时成立 |
| 渡轮规定载况吃水1.4米 | 船舶资料p01；B规定p02不支持本次擅自改变载况 |
| C开放但灯必须可用并在安装状态核验 | 公告p02 |
| 灯本体可用，坏的是支架 | 更正录音p01/p02与现场可观察设备 |
| 使用船内备用电池，主发电机暂不开 | 更正录音p04与现有电池资料 |

**制作期结论：**本次受支持方案中，A不可行；B即使开泵仍不可行；C在维修与核验完成之后可用。

**不能采用的推理：**“C requires a beacon”只表达必要条件，不能仅凭这句话推断所有其他要求都不存在。本关结论还依赖C当前开放、许可、船舶资料和规定检查范围等已明确条件。自由文本的only if不能由解析器粗暴改成if and only if。

**运行时区别：**候选计划可以提前采用C；当前离港仍不就绪。谜题不得把“计划有解”写成`ferry.departed=true`。

**反例：**B+开泵仍失败；另一艘小船的数据不适用；把英尺与米混同不能成立；新提议未在当前行动域中实现时先说明范围，不判成语言错误。

**学习：**主要观察R03、R09、L03；选中C一次不证明三个目标全部独立完成。已从船上得知支架损坏，再听录音不是该事实首次纯听觉理解。

## 12.2 PZ-Q102-ACCESS：西工坊的三种进入方法

**玩家目标：**进入工坊、取得替换支架、保留安全回程。  
**空间：**R1-S05外场、R1-S07检查间、R1-S06内场及原有横闩捷径。  
**新增局部材料：**`PZ102-R-WORKSHOP`与`PZ102-R-PANEL`补齐第四部分的材料别名；不修改第三部分已定装置事实。

| 方法 | 操作 | 后果 |
|---|---|---|
| 正面处置 | 明确确认遭遇；战斗系统交回合法成功结果 | 机械disabled；可进入取件 |
| 局部停机 | 到检查间，按本地控制说明选择隔离 | 机械isolated；侧门与安全路线可用 |
| 潜入 | 启动固定检查，沿检修侧道行进 | 机械focused；侧道开放，前侧扫描仍危险 |

局部控制用工坊储备；船内电池留在船上；固定灯架不是渡轮导航灯。主发电机未获准启动，不是解谜时必须试出的暗门。

`focused`持续到明确取消，读材料和保存不会结束。正面危险双向存在，潜入后不能沿仍危险的前门无提示离开。打开内闩后，其捷径不受模式联锁影响。

取支架只产生一份受控物品迁移；多试几种方法不复制支架、不重复发任务奖励。玩家可以改换方法，物理状态保留，不要求重开任务。

**反馈：**误以为固定检查等于完全停机时，设备或风险预览指出仍有扫描区；无法理解说明时分离语言与路线提示。完整帮助根据现在的位置、模式、已取物品和门状态产生合法回程。

## 12.3 PZ-Q102-TEST：修复并验证当前配置

| 尝试 | 结果 |
|---|---|
| 先安装、再接电、后测试 | 可接受 |
| 先接电、再安装、后测试 | 可接受 |

这段允许直接操作并观察，不需要再额外回答“先做哪一步”的选择题。若安排可选流程复盘，必须标为学习练习，不发第二份维修奖励。

# 14. 时间线：记录时间不等于发生时间（PZ-14）

**单元：**`PZ-Q202-TIME`，父任务Q-202，R2-S03/R2-S04。  
**局部新增范围：**转移记录M-12的登记副件，不是导师扣押记录，不改写导师D-1仍在世的既定证据，也不公开私人姓名。

## 14.1 材料与结论

全部时间指同一地方档案日：出发人员在14:10离开前已查验授权；接收员记录14:40抵达；档案员在16:05把出发和到达记录抄入总账。授权原件没有可靠的签发分钟。出发记录的一个副本不是另一位证人的独立观察。

|---|---|

| 16:05才真正到达 | 与14:40现场到达记录冲突 |

| 中央办公室故意拖延登记 | 信息不足 |

“信息不足”是一个完成判断，不是必须再猜一次直到出现真或假。玩家可以标出已有材料的范围或提出需要补充什么，但系统不要求找不存在的反证句。

该四事件样例的24种全排列只有一种满足已给关系。把关键关系删掉后，多个顺序会成立；加入循环约束时没有顺序成立。制作工具必须报告这种变化，不能仍将旧答案标成唯一。

其他时间谜题允许多个合法偏序。只检查“授权在出发前”等真正给出的关系，不能因为玩家交换了两件彼此无约束的事件就判错。

本单元是Q-202的一段调查，不替代该任务在第五部分保留的视觉信息长写作，也不额外强制写一篇作文。

## 16.3 实际交互与错误反馈

玩家在装运板上安排两趟，比较货单与安装者录音，确认本次偏好。拖拽阶段不消费仓库物资。确认后由第四部分工作单原子预留、行程执行、交付并生成回执。

若超载，说明相关趟的容量冲突；若把工具与灯放同趟，说明“较早一趟”未满足。具体反馈透露关系时按帮助记录，不自动标独立听懂。

不能通过刷新界面多出第三趟，也不能把第三部分的快速旅行当成无条件运货。新提出第三趟属于行动范围外提案，可解释原因，不判成英语错误。

这段的短说明可进入Q-603已有运输方案；第五部分所规定的安全段后论证写作仍保留，不被一个装载小游戏替代。

# 17. 试验推理：结论应该到哪里停止（PZ-17）

均为同一A控制器，已做规定隔离检查，每次十分钟。负荷数值使用试验台内部单位，不要求真实电气专业计算。

## 17.4 实际玩家工作

完整提示给出可比组合和有限结论，但不替玩家决定下一章政策。对于文本解释，优先使用第五部分的分范围反馈；模型没有足够把握时澄清，而不是自行发放技术验证回执。

# 18. 章节分布、数量与节奏（PZ-18）

Q-102有四个单元，但不加四次任务奖励。四个单元中的交流使用原有草稿，不增四篇文章。写作可以承担独立的沟通问题；普通结算感谢不因此变成新谜题。

## 18.2 复合谜题的原则

复合不等于每一步都重新用不同包装问同一个答案。航道判断输出计划方向；工坊输出实际物品；维修输出当前设备证明；沟通输出玩家已确认意图。每一步解决不同缺项，共同由任务系统结算。

每个区域至少交替出现现场操作、信息比较和有实际对象的沟通；保留纯探索、战斗、人物场景与休息。关键长文或长写作之后避免立即强制另一个高负担单元。读听写仍按第五部分的全章覆盖与预算执行。

## 18.3 主线对应范围

附录A列出32任务的家族、已有场景、第五部分主要目标与写作形式。家族绑定说明在哪里制作什么，不表示所有材料、音轨和谜底已完成。更精细的单元拆分必须保持主线依赖，不增加隐藏结局门槛。

# 19. 内容生产、可解性与AI边界（PZ-19）

## 19.1 生产顺序

先定义玩家目标与受支持行动域；写出固定事实、变量、可行解和需要保留的未知；设计可取得的材料与观察；再编写英文、人物表现和场景操作；最后验证文本、逻辑、回程、提示与6.5目标。

不能先随机生成十封相互矛盾的信，再让AI猜作者想要哪个答案。反派说谎可以是剧情，但必须受知识、动机与替代证据约束，不能用“他可能在说谎”解决任何矛盾。

## 19.2 三种不同的验证

| 验证 | 解决的问题 | 不解决的问题 |
|---|---|---|
| 约束与状态求解 | 规则有无可行方案、死路、唯一/多解、配置失效 | 英文是否表达清楚、玩家是否找得到线索 |
| 信息与来源审计 | 可见材料是否支持结论，缺失事实是否使多个解释成立 | 自动证明玩家已经独立理解 |
| 实际试玩与语言校准 | 输入、材料、语音、逻辑总负担是否符合6.5目标与冒险体验 | 单靠少数通过率证明长期提分 |

制作期可用反事实候选世界检查信息缺项：若隐藏吃水资料后，玩家可见材料同时允许“小船可走B”和“本船不可走B”，就不能宣称仅凭这些可见材料能唯一判定当前路线。该方法只能在声明的候选域中检查，仍要人工核对英文含义和实际可访问性。

## 19.3 必须主动检查的漏洞

已知正确答案却缺关键依据；旧记录没有被有效修订就当作作废；来源副本充当独立证据；未知字段被默认false；只有一种加点可取得必需信息；状态复位把已取物品复制出来；旧证明在新配置继续有效；提示让玩家执行当前不合法动作；自由文本服务直接写结局；地图同端点通路混同；多解题只接受参考答案；只改名字就当全新学习证据。

这些检查不是“内容多以后再说”的优化项，而是主线发布前必须解决的功能问题。

## 19.4 AI的权限

AI可以在受控事实下草拟不同口吻和文体、解释已授权材料、提出候选反馈、辅助制作变体与反例。所有新材料都要经过事实、来源、可行性和语言目标核验。

运行时不得让模型直接决定物品归属、改变当前答案、加入无依据新线索、自动执行最终行动或用它的自报置信度放行。自由文本超出模型把握时保留玩家意图并请求澄清。

主线事实和解法不实时随机生成。可重复练习可从已验证变体选择；同模板改数值不自动成为独立新情境。变体必须保留家族关系，修改关键事实后重新核查所有约束、答案、提示和配套音轨。

# 20. 模块接口、所有权与版本（PZ-20）

## 20.1 谜题输出四类受控结果

| 输出 | 内容 | 接收方 |
|---|---|---|

不输出`grant_xp`、`quest_closed`、`all_towers_ready`、`npc_dead`等任意世界写入。谜题可以引用现有行动回执，不自行生成同义的另一份权威状态。

## 20.2 与第四、五部分接入

Q-102-NAV/BRIEF提供与既有`O-102-PLAN`一致的意图候选，正式确认由第四部分完成。Q-102-TEST使用`O-102-FIX`与`O-102-TEST`的设备事实和版本证明，不建立第二套灯状态。Q-102-ACCESS取得同一个有来历的支架，不按方法发第二份物品。

时间线、地图、货载和试验的新增数据均是局部制作设定，不能当成提前公开的世界真相或旧文档已存在的内容。人物、设备及工作单的最终ID由第九、十二部分统一。

## 20.3 恢复和异步结果

保存玩家草案、候选关系、已执行回执、材料版本及辅助范围。载入旧世界时，当前交互上下文更新，拒绝尚未提交的旧请求；已提交世界回执按该存档保留。学习暴露历史按第五部分处理，不灌入角色尚未获得的未来资料。

重写正文、修改相关配置或切换内容版本使有关旧检查失效；不相关操作不触发全表重做。迟到语言反馈只归原尝试，不执行世界动作。删除档案后迟到结果不能重建被删除文本。

内容版本改变时保留进行中版本或明确迁移。题目、答案、录音和提示不能混用不同版。迁移无法保留进度时提供已定义的安全恢复并说明影响，不伪造玩家从未做过。

# 21. 制作工具与调试视图（PZ-21）

制作人员需要同时查看以下信息：目前哪项约束不成立、对应哪个权威字段、材料依据在哪里、玩家是否能取得、哪些方法可以恢复、提示会透露哪些目标、上次证明为何过期。

# Codex交接：第九部分

## 先读

`NPC_Faction_System_v0.1.md`、`NPC_Change_CR-NPC-009-001.md`，再读dependencies中的相关第1—8部分。本包冻结参考数据，不要求重新调用build_data生成。此包不应单独用于“自动做出全游戏”。

## 先跑检查

在本包根目录执行：

```bash
python validation/run_validation.py
```

仅使用Python标准库。测试相对当前文件定位数据，不依赖下载目录、网络或其他包。测试会重写run_log.txt与validation_report.json，因此需要比对MANIFEST时应在运行前核对原始包文件。

## 初始集成契约

任务提供可验的工作与承诺回执；NPC消费它们，但不根据未确认聊天创建世界事实。设备与工程提供事实检查，人物请求只产生待批准请求。战斗冻结实际队伍；安全点同步归还收藏和切换身份。学习观察写入独立通道，不反写NPC态度。

## 参考代码不是生产安全边界

`Consent`、任职记录与`verified_receipts`参数假定已由上位权威检查。它们不是客户端可以自报的凭据。参考程序没有身份认证、真实数据库事务或任意自然语言过滤。所有输入必须由生产服务器/本地可信状态机重新构建，不能信任玩家文本、模型输出和脚本中的一句true。

## 实现前不得自由发明

不得新增好感阈值、超时死亡、永远失去同伴、政治立场加伤害、声望限定核心装备、关系许可一键修塔、道歉重置责任。数据里未完成的内容要明确标记，不能全部返回成功。

## 必测跨系统问题

不招任何同伴仍能做主线；领到但未安装不是完成；发过的信撤许可后仍是历史；档案摘要可查不等于地址可公布；切存档后延迟对话不能剧透；一份遗物只有一个持有人；同NPC不能同一工作步施工和出战。

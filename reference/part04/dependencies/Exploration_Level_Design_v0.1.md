# 第三部分：地图、探索与关卡结构

文档：`Exploration_Level_Design.md`  
版本：`v0.1`  
项目：《雾海档案：第七座灯塔》（暂定名）  
上位文档：`Game_Design_Core_v0.1.md`、`World_Story_Bible_v0.1.md`  
配套参考：`Exploration_Layout_Reference_v0.1.json`  
用途：把剧情节点转化为可进入、可移动、可调查、可返回、可测试的空间；约束第四部分任务图、第六部分谜题、第十部分界面和第十二部分实现。

## 文档效力与本轮范围

本版是供项目采用的探索设计基线，不表示所有数值、游玩时长和几何布局已通过试玩。未特别标注的体验与权限规则按基线处理；场景数量、尺寸、行走时间、热点数量为待验证初值。

本轮完成世界与区域连接、78个场景空间的登记、各区域主干与返程设计、6个样板场景的灰盒坐标和交互、核心门禁与失败恢复契约，以及验收清单。其余场景先落实用途、相邻关系、关键动作和进入/返程条件，不假装已经逐一完成碰撞几何或英文材料终稿。

配套JSON是设计参考，不是正式运行时存档格式；其中语义门禁不能直接交给任意字符串求值器执行。第十二部分再统一引擎、正式数据结构和接口。此时不运行游戏引擎，不制作正式美术，不实施第四至第十二部分的完整系统。

全文属于制作资料，包含谜题答案和场景解锁条件，不应原样展示给玩家。

# 1. 本部分确定的游戏形态（EXP-01）

## 1.1 视角与控制方式

采用**偏俯视的二维步行探索**。场景可以画成有一定侧面透视的二维插画，但移动逻辑按一个平面处理；不做3D模型、真实等距多层遮挡，也不做横版跳跃平台游戏。

世界旅行使用节点地图；进入地点后，玩家控制可见角色，在场景中走到门、人物、文献、设备和物品附近互动。不是点地图后只打开一页文字。

鼠标点击地面移动为默认，键盘方向移动为等价方式。两者必须使用同一可通行区域、碰撞规则和风险边界，不能出现鼠标绕得过去而键盘被隐形墙挡住，或键盘斜向穿墙。

不要求跑跳、攀爬反应、点击移动物体或快速输入英文。攀梯、跨越和搬动物体是站在确定位置后发起的动作，使用短动画或状态切换表达。

## 1.2 为什么先选择这个形态

这个选择满足本项目的实际约束：保留位置、距离、路径、机关和角色存在感，同时让场景背景、少量角色动画和可复用装置承担主要表现。这里是项目取舍，不是宣称这种形式对所有学习游戏都更优。

基本角色表现先按四朝向站立与移动设计；移动方向可以连续，显示方向映射到最近朝向。灰盒阶段可用简单形状替代。正式样章优先完成主角；同伴通过队伍界面、立绘和指定站位参与，不要求每名同伴都持续跟随寻路。后续出现跟随实体时，不参与阻塞，也不触发主角尚未确认的门和战斗。

## 1.3 相机与场景大小

普通房间使用固定相机，长街、矿道和大型机房允许有限平移。默认不旋转、不动态改变朝向，不让同一个出口在进入后突然换到另一边。

| 项目 | 待验证初值 | 使用边界 |
|---|---|---|
| 灰盒设计基准 | 1280×720的16:9视窗 | 运行时自适应；不是把世界和文字硬编码为一张图片 |
| 普通空间 | 约1个视窗，少数1.5—2个视窗 | 更长空间优先拆成有明确转折的独立场景 |
| 无障碍穿过单屏 | 约8—12秒 | 仅用于调移动速度；不含阅读、停顿和解谜 |
| 长空间纯移动 | 尽量不连续超过约25秒 | 超过时需要有新观察、路线决策或合理分段 |
| 交互目标点击区 | 先按不小于48×48逻辑像素测试 | 可以扩大点击区，不必把物体美术画得同样大 |
| 主要通路 | 容纳主角碰撞体并有转向余量 | 导航烘焙/验证必须考虑角色半径，不能只查中心点 |

这些目标不构成计时挑战。玩家阅读缓慢不会受罚。长文阅读也不计入“移动效率差”的统计。

# 2. 四层空间与三种不同地图（EXP-02）

## 2.1 四层结构

| 层级 | 负责什么 | 不负责什么 |
|---|---|---|
| 世界地图 | 地区之间的旅行、航路和章节开放 | 不模拟连续海洋驾驶 |
| 区域地图 | 该地区地点、连接、已知入口和安全返程点 | 不自动整理正确谜底 |
| 可探索场景 | 步行、调查、谈话、取物、现场操作与遭遇 | 不承包整章全部任务状态 |
| 近景操作面板 | 控制台、地图证据、写作、档案、设备细部 | 不计成一张新的可探索地图 |

“场景”有自己的局部坐标、可行走区域、出口和持久状态。只更换天气、NPC站位、灯光或破损外观，不算新场景。

战斗可以进入独立战斗表现层，但不是新的探索地点；其结果返回发起遭遇的场景实例。

## 2.2 导航地图与任务证据地图必须分离

本游戏同时存在三种常被混淆的东西：**帮助玩家找到场所的地图、世界中人物制作的地图材料、玩家对材料的解释。**

导航地图可以告诉玩家调度室在何处，也可以标注已发现的墙和道路。它不能在玩家尚未理解航道公告时，把正确航道涂成绿色。

作为证据的旧地图、航道图和沉降记录有作者、日期、比例或不完整范围。它们可以不完全准确。玩家对这些材料的标注是一个假设，不直接写成世界事实。

例如旧都：区域界面先显示玩家已经见到的路口和居民活动点；旧街名及某条道路是否通向北站，需要通过材料和调查建立。不能在入口的全知小地图上提前画出“关押导师的房间”。

## 2.3 宏观认知不等于可进入

玩家可以一开始就在世界地图上知道六个地区与第七塔的公开名称。具体隐蔽地点只在听说、看到入口或获得定位材料后出现。公开的“第七塔”不是需要最高感知才能发现的隐藏地图。

第一章未完成前显示微光号泊位位置，不等于玩家已经拥有微光号。民用渡轮与巡灯船的入口、实例和任务物品必须分开。

# 3. 世界旅行、区域移动与快速返回（EXP-03）

## 3.1 首次跨区顺序

| 新增旅行连接 | 成立条件 | 玩家看到的理由 |
|---|---|---|
| 搁浅海岸→盐雾港 | 序章救援与接应成立 | 接应船带幸存者入港 |
| 盐雾港→苔林 | Q-104完成，取得微光号使用权与跨区委托 | 有船、有航路、有下一步核查对象 |
| 苔林→矿区 | 转移链及检修批次方向取得，地区出口条件成立 | 前往批次对应的工业地区 |
| 矿区→学城 | 矿区处置与核验材料就绪 | 将样本与记录送去验证 |
| 学城→旧都 | 北站定位完成，章节出口成立 | 进入已被核验的位置，不盲闯全岛 |
| 旧都→边境 | 导师救援、共同处置授权和章节出口成立 | 取得当前风险并组织最后准备 |
| 边境→第七塔 | Q-604确认，基础保全与进入条件满足 | 明确进入最后行动阶段 |

不使用“人物等级达到20才能坐船”或“雅思词汇掌握度达到80%才能进旧都”。必要通行、工具与通信条件从主线获得，不要求随机掉落或可错过同伴。

## 3.2 跨区旅行如何操作

在当前地区的安全出发点或微光号航图处，选择已开放目的地，查看可行航路后确认。普通旅行合并已走过的连接，显示短航行过渡，落在目的地登记的靠泊点。

不会为了从边境回港口核对一份资料，强迫玩家连续打开五次船票菜单。也不会把合并旅行解释为绕过尚未处理的封锁、正在进行的护送或未开放的地区。

普通已开放航线不收取可能让玩家被困的燃料门票，不投掷不可回避的随机伏击。任务中专门安排的护送与运输使用自己的资源与行程规则，不能藏在普通快速旅行内收费。

## 3.3 区域内返程

一个地点成为快速返回点，需要：玩家确实到访、已经登记、安全条件成立，并且当前路线允许到达。地图发现不等于自动获得传送权。

常规每地区提供入口/生活中心和主设施安全返程点。塔站返程点在安全工作完成后登记；它缩短后期核验，不把所有塔自动标为独立运行或分布式就绪。

快速返回只折叠已安全走通的路径，不跨越未解决的遭遇门、单向阻断、护送承诺或正在执行的机关阶段。遇到这些情况，界面说明具体原因并提供最近安全点，而不是笼统提示“现在不能传送”。

## 3.4 第六章和终章的例外

第六章Q-602需要跨区核验。各塔安全返程点与微光号共同承担这个功能。玩家仍要处理真实缺项，但不重走此前已经解决的矿道和塔站战斗。

Q-604确认后暂停终章外的旅行，保留明确命名的终章前存档。进入第七塔后可以在已安全处理的内部空间往返，不能在战斗途中直接跳回旅舍。结束后提供“终局前继续探索”，保持结局快照独立。

# 4. 场景发现、地点访问与知识记录（EXP-04）

## 4.1 不能用一个completed覆盖全部状态

| 状态维度 | 示例 | 如何取得 |
|---|---|---|
| 地点认知 | 未知／听说／看见入口 | 实际信息与视野 |
| 到访 | 未到访／已进入 | 玩家实体完成场景进入 |
| 当前通行 | 未核验／可通行／被阻挡并说明原因 | 当前世界规则 |
| 物理变化 | 门是否打开、设备是否隔离、物品在哪里 | 已提交的现场动作 |
| 遭遇状态 | 未处理／暂时回避／已处置 | 受控遭遇结果 |
| 任务进度 | 某任务目标是否完成 | 第四部分任务规则 |
| 学习观察 | 接触、帮助、尝试及评价 | 第五部分，不由地图访问代替 |

发现工坊、进入工坊、拿到支架、修好导航灯、完成撤离，是五件不同的事。

不使用“本场景100%”作为主线门槛，也不通过剩余线索数字向玩家泄露未发现的剧情秘密。可选收藏统计可以单独显示。

## 4.2 关键交互必须可以找到

进入场景后先建立位置感：来路、主要出口、显著地标和当前值得调查的对象。关键入口有明确视觉或文字指示，交互目标能够主动高亮，也能通过键盘焦点依次访问。

高亮只显示当前可感知的物件类别和标签，不显示藏在柜里的证据内容，不穿墙标出隐藏人物，不标“这是正确答案”。关键证据不能放在只能靠碰运气点击一个像素的位置。

感知与其他成长能力可以提示额外痕迹、可选奖励、捷径或准备机会。所有基础加点组合仍有取得唯一主线信息的办法。

## 4.3 材料取得与打开

现场纸张、录音和图表进入材料档案后，可以随时回看；关键信息不只播放一次。移动据点、场景变体和后续剧情改变原地点时，已经取得的材料保持原版本。

自动保存材料只表示取得，不表示理解。玩家没有逐一打开所有材料，也可能凭现有事实或帮助作出有效方案；任务不能因此人为阻止行动。学习系统另外记录证据不足或帮助条件。

不能用“必须点击完六份文献”替代真实规则检查。标准路径要提供读听写机会，而不是靠点击配额证明掌握。

# 5. 场景交互与输入规则（EXP-05）

## 5.1 基础动词

| 动词 | 场景中的含义 | 提交边界 |
|---|---|---|
| 观察/检查 | 查看现场状态、物体和说明 | 取得材料或记录观察，不擅自操作设备 |
| 交谈 | 获取说法、提出事实问题、请求许可 | 人物说法和权限变更分开 |
| 拾取 | 将可取得物品转入持有状态 | 唯一任务物品只有一个合法位置 |
| 使用/安装 | 用持有物品或现场工具改变装置 | 校验条件后原子提交 |
| 操作 | 调节阀门、选择设备模式、启用局部装置 | 可恢复机关状态，由确定规则验证 |
| 比较/记录 | 打开证据和笔记工作区 | 笔记不自动变成已证实结论 |
| 写作/发送 | 编写说明，确认通信内容 | 草稿、确认行动、语言评价分别记录 |
| 通行/旅行 | 使用门、梯、出口或船只 | 先检查门禁与落点，再完成迁移 |

一般可拾取物点击后直接取；可能有两种以上意义的设备先打开简短动作菜单。关键不可逆动作单独确认；普通查阅和每扇门不重复弹确认框。

不要要求玩家拖动背包里所有物品逐一试配所有热点。对不匹配的物品显示具体类别原因，不消耗物品，也不扣学习表现。

## 5.2 点击与键盘必须等价

点击交互目标时，角色先沿有效路径走到该目标的操作站位，再执行动作。不能从屏幕另一端直接拿走柜中物品。站位不可达时说明阻挡类别，不能穿墙或瞬移。

键盘焦点切换到目标后，执行同一套接近与操作规则。切换目标不等于自动穿越危险区域。

输入草稿时，WASD、空格、回车和快捷键归文字编辑器；不能把句子里的字母解释为移动或触发设备。关闭面板后不补执行之前排队的移动或离港命令。

## 5.3 状态模式

探索、接近目标、近景交互、阅读/写作、交谈、战斗、场景迁移是互斥或明确嵌套的输入模式。任一时刻只允许一个模式处理关键动作。

阅读/写作、近景比较和游戏暂停时，不推进会惩罚玩家的巡逻、风暴、机关倒计时或护送危险。恢复后不会补算暂停期间的伤害。

## 5.4 出口与落点

每个出口有稳定编号、目标场景、目标入口、站位和进入条件。到达出口后按明确操作进入，不单凭踩到屏幕边缘就强制切换。

落点必须位于有效通行区域、远离敌人自动触发区，并能到达至少一个可返回或继续推进的位置。迁移失败时停留或恢复到原场景的安全边界，不消耗资源、不重复执行剧情。

角色出现后不自动触发对应反向出口。遇到版本变化使落点失效，只能采用该场景预登记的安全备用点，不能在任意最近坐标生成角色。

# 6. 门禁、捷径与能力路线（EXP-06）

## 6.1 五类可以使用的限制

| 限制 | 合理例子 | 必须具备的条件 |
|---|---|---|
| 现场危险 | 积水、失控机械、损坏升降机 | 可检查、可处理、可复位或可替代 |
| 实际授权 | 记录调阅、设施接管 | 说明所需授权来源，不用隐形好感顶替 |
| 物件与工具 | 替换件、检修工具、固定绳索 | 主线路径能够获得，不随机丢失 |
| 可验证的信息定位 | 不知道哪条旧街通向北站 | 足够证据存在，提示不以属性独占 |
| 已确认的阶段变化 | 最终起航后外区暂时不可达 | 事前说明范围，保留存档 |

不使用英语分数锁、文献打开数量锁、提示使用次数锁或随机开门成功率作为主线门禁。

“信息定位”不是要求玩家必须点到某条标准思路。已经依据充分信息走到正确位置的玩家可以继续，学习记录保留真实条件。

## 6.2 门禁反馈的三层

第一次遇到受限地点，至少告诉玩家**是什么阻止进入、可以去哪里处理或核验、当前能否返回**。

“门锁着”不够。可以写“记录室由保管人管理；调度台能够办理本次核查的访问手续”。不要写“先把文章读到第312词”。

仍未知的具体原因可以保留，但要有可执行调查方向，不能只显示灰色按钮。

## 6.3 捷径的目的

初次探索承担定位、信息与危险；完成后返程应减少已经解决的操作。

典型方式是工坊内侧横闩、矿井修复升降支路、实验场后勤门、旧都救援便道。捷径不是魔法传送，也不能从外面提前绕过整个问题。

单向入口或内部落差必须有退出保障：可回返、可开启后门、可恢复检查点或明确的替代路径。使用有限消耗品打开唯一出口时，资源不足不能制造不可恢复状态。

## 6.4 加点只改变方法

加强体魄可以减少环境代价，力量可以打开额外侧门，敏捷可以让某条非计时路线更便利，感知可以发现准备线索，机巧能力可以节省一次工具操作。

详细能力与阈值交给第七部分。关卡只声明“可选能力入口”，不自行创造一个必须达到12点敏捷的主线悬崖。

没有任何特殊加点、没有特定同伴、没有随机稀有装备的基线角色，也必须存在完整主线路径。

# 7. 场景类型、危险与节奏（EXP-07）

## 7.1 场景的职责

| 类型 | 核心作用 | 常见结构 |
|---|---|---|
| 生活中心 | 定位、人物、选择任务、休整 | 1个明显中心，若干短支路 |
| 调查空间 | 取得相互可比较的信息 | 多来源并行，不强制唯一查看顺序 |
| 操作空间 | 改变通路与装置 | 机关状态可见，材料在合理位置 |
| 危险空间 | 战术、护送、有限资源取舍 | 可见威胁，先观察再确认进入 |
| 收束空间 | 写作、方案确认、结果表达 | 安全、可中断、材料随时可回看 |

同一场景可以跨类型，但不能在玩家写作时偷偷保持危险空间的惩罚计时。

## 7.2 普通区域的推荐节奏

先抵达生活中心，再开放两到三条调查/行动方向；各方向支持同一个地区问题，在主设施汇合；高潮后开放返程捷径，在安全地点看到后果。

“循环”只描述空间连接，不表示做完一题必须回中心交作业。通信、笔记和任务状态可以原地更新；必须面对面交接时才安排实际返回。

单屏先按1—3个当前重要交互、少量可选生活互动测试，总可见功能热点尽量保持在6—10个左右。它不是阅读量上限；较长材料通过独立档案面板提供。

## 7.3 战斗触发

敌人与装置威胁应能观察。穿过风险边界前给出清晰提示；确认后进入战斗。已处理的主线遭遇不因退出场景自动重生。

偶遇与支线遭遇使用独立实例；不把玩家赶往任务目标的唯一通路变成可无限刷怪的走廊。玩家失败返回相应战前点，之前的材料和草稿不删除。

不承诺全流程无战斗。某些工坊、守卫或设施有替代方法，但部分主线高潮仍包含战斗。

## 7.4 潜入与护送不考阅读速度

潜入以站位、遮挡、装置模式和明确行动步骤为主要决策。关键观察动作可暂停，必要巡逻可推进一格而不是等现实秒表。样板直接采用持续检查状态，避免同时读英文和抢转身间隙。

护送以“准备—确认出发—解决一段—进入安全点”为循环。查看资料不推进下一段。不做被护送NPC用独立寻路不断卡墙、掉队和死亡的默认系统。

# 10. 样板关卡：Q-102《最后一班渡轮》（EXP-10）

## 10.1 这次实际制作什么

样板采用盐雾港中的6个场景：渡运广场、调度室、民用渡轮、西工坊外场、西工坊内场、配电检查间。它们在完整版继续使用相同编号，不为演示另写一套互不兼容的港口。

演示开始条件是玩家已经取得临时检修委托；Q-101不在该次演示范围。这个测试入口可以设置世界许可，但不能虚构玩家已获得阅读、听力或写作成绩。莉娜可作为一名协作同伴出现，但本任务不依赖她在队。

本任务的目标是**恢复渡轮的安全撤离能力并向负责人说明可执行方案**，不是取得微光号，也不是直接离开第一章。

目标游玩时长先按约45—70分钟测试，包含阅读、重听、探索、一次取件过程、写作和结算；不是要求玩家在70分钟内通关。

## 10.2 固定事实，不能更改

| 事实 | 来源安排 | 对关卡的约束 |
|---|---|---|
| A航道关闭 | 广场现行公告 | 不能通过修好设备重新开放A |
| B航道需要辅助泵，最大吃水1.2米 | 调度室B航道规定 | 开泵也不能让1.4米的渡轮进入 |
| 渡轮吃水1.4米 | 船内规定载况资料 | 本任务不支持任意抛弃救援物资来变成另一船型/载况 |
| C航道开放，导航灯必须可用 | 广场现行公告 | 路线是否可行与设备实际状态有关 |
| 导航灯本体可用，支架损坏 | 调度更正录音和现场检查 | 不设计“找一盏全新的灯”为唯一解 |
| 替换支架在西工坊 | 调度录音与工坊实际货架 | 三种进入方法取得同一个必要物品 |
| 船内有充满电的备用电池 | 船内设备检查 | 不把它改成藏在可选宝箱的随机掉落 |
| 主发电机尚未安全隔离，不能启动 | 调度录音与检查牌 | 本任务结束也不能把它标成已经安全修复 |

A/B/C是航道方案，不是样板中三张可步行的地图。地图中的工坊分路与航道选择是不同问题。

## 10.3 新增的局部关卡事实

为了实现三种工坊路线，本部分增加以下**受控的本任务局部设定**：工坊维护机械及其检修控制器有独立储备，不需要启动港口主发电机；场内有固定测试灯架，能够让机械保持检查注意状态；检修侧道不在该检查扫描区域内。

这些是本任务明示并可验证的虚构设备规则，不能让玩家凭现实电工知识自行猜到。不能后来又写成“主发电机一断电，所有工坊控制器都立即失效”。

固定测试灯架不是渡轮导航灯，独立储备不是船内备用电池；三者分别标识。玩家不需要拆走救援必需电池来进行潜入。检修侧门的模式联锁在active时关闭，在focused/isolated/disabled时开放；已开启的横闩捷径不受这个联锁影响。

样板之外的泊位、塔基、旅舍和记录室出口保留“演示范围边界”，不写成世界中永久封锁。完整版接入登记目标后才能取消边界。配套数据对这些外部出口标明尚未提供目标几何，不能伪造已经测试了完整第一章。

## 11.2 渡运广场：负责定位，不负责告诉答案

玩家从靠泊侧进入，立刻能辨认中央公告、右侧渡轮、调度室和西侧工坊方向。

| 交互 | 站位 | 实际结果 |
|---|---|---|
| 现行航道公告 | (43,42) | 获得A/C条件材料，可在档案回看 |
| 区域位置图 | (60,36) | 标注真实地点与已发现入口，不高亮正确航道 |
| 接应联系人 | (79,64) | 获取当前需求、离港后的回执与记录访问方向 |
| 工坊回程门外侧 | 对应出口 | 起初显示内侧横闩；不会因角色力量高就自动绕过全部取件过程 |

此场景不持续播放覆盖关键信息的喧闹广播。查看音频或材料时降低环境声，不改变原始录音内容。

## 11.3 调度室：提供更正与限制

角色从下方进入，柜台与设备构成明确的交互区域，座椅和背景工作人员不堵路。

| 交互 | 站位 | 实际结果 |
|---|---|---|
| 修订调度录音 | (69,51) | 播放更正、支架位置、主发电机限制；可重播/分段/字幕 |
| B航道规定 | (27,45) | 取得辅助泵与最大吃水条件 |
| 哈文工作台 | (49,54) | 咨询任务目标，确认玩家提出的行动内容 |

录音打开后保存到档案，声音不是一出门就失效的谜题机关。未听懂时可以获取帮助，世界结果不降级，学习记录保持真实输入条件。

“记录保管间”供Q-103使用，不是Q-102的隐藏必经房间。提前获得工单可以保存为待核验线索，但不能自动完成事故责任判断。

## 11.4 民用渡轮：检查、安装与写作

这是停泊中的民用船，只在Q-102离港提交前可进入。船舱不用另开一张加载地图，控制近景作为本场景面板。

| 交互 | 站位 | 实际结果 |
|---|---|---|
| 船舶资料牌 | (21,42) | 取得1.4米吃水和规定载况 |
| 导航灯装置 | (74,35) | 检查灯体、安装支架、执行测试 |
| 备用电池座 | (75,75) | 确认现有储备并连接，不依赖工坊控制器 |
| 写作台 | (26,76) | 保存草稿、提出路线、确认行动、申请离港 |

玩家可以先检查船，再去听录音；也可以先拿支架，再返回检查。不能因为“还没播放标准剧情顺序的对白”就拒绝已经合法获得的物品。

先安装支架或先连接备用电池均可，最终测试必须在正确配置下执行。改变配置后，先前测试记录不能继续充当当前可用状态。

## 11.5 西工坊外场：让路线选择可以看见

外场提供观察机械的安全位置、明显的正门、检查间门和维修路线标记。玩家不需要找到一个隐藏地板像素才能知道有侧路。

正门的风险在进入前说明。选择取消时停留安全区域；选择进入时才发起工坊遭遇。未选择战斗时仍可转去检查间。

| 交互 | 站位 | 实际结果 |
|---|---|---|
| 检修入口图 | (20,74) | 标明检查间和检修侧道，不标最终航道答案 |
| 观察维护机械 | (73,32) | 看见扫描区域和独立装置状态，提供决策信息 |

## 11.6 配电检查间：两种非战斗解决方法

玩家能清楚区分港口主发电机的检查牌与工坊局部控制器。它们不能用一个含糊的“恢复电力”按钮混在一起。

| 交互 | 站位 | 实际结果 |
|---|---|---|
| 主发电机检查牌 | (73,52) | 显示隔离尚未完成；在本任务中不可启动 |
| 工坊局部控制器 | (25,60) | 选择局部隔离或固定检查模式 |
| 维护说明 | (25,81) | 提供执行条件、局部储备和安全侧道的信息 |

局部隔离需要选择对应工坊装置，并核对状态变为隔离；错误选择不扣除唯一电池。固定检查模式启动既有灯架，使注意固定在检查区，直到玩家明确取消，不在玩家读完前自动失效。

具体英文材料终稿及逐项提示交给第五、第六部分，本部分先固定动作语义与设备结果。

## 11.7 西工坊内场：共同目标与回程

无论以战斗、隔离还是潜入方式进入，都抵达同一空间实例、同一替换支架。

| 交互 | 站位 | 实际结果 |
|---|---|---|
| 支架货架 | (82,45) | 唯一支架从货架转入玩家持有 |
| 回广场的横闩 | (11,77) | 开放永久双向捷径，不自动领取支架 |
| 待核验工单 | (79,75) | 提供可选后续调查线索；不直接证明事故蓄意 |

检修侧道进来的玩家可沿上方和左侧通路避开扫描区，取得支架后开横闩返回。自动寻路应优先采用已知安全路径；若目标需要穿过风险区，先说明风险，不能因为点击了远处物品就暗中开启战斗。

本任务工坊维护机械与Q-104塔站机械是不同实例。美术可以共享，但状态、奖励、战斗记录必须分别保存。

# 12. 三条取件路线与状态规则（EXP-12）

## 12.1 路线比较

| 方法 | 实际路径与动作 | 得到的物品 | 方法差异 |
|---|---|---|---|
| 正面处置 | 广场→外场→确认遭遇→工坊 | 替换支架 | 战术与补给压力；失败回战前点 |
| 局部停机 | 广场→外场→检查间→隔离工坊装置→侧道→工坊 | 同一个替换支架 | 条件与对象识别；机械保持隔离 |
| 潜入 | 广场→外场→检查间→启动固定检查→安全侧道→工坊 | 同一个替换支架 | 对注意区域与路线的判断；不依赖倒计时 |

三条方法都不需要特殊加点。后续构筑可以让过程更有效率，但不能把其中一种主线最低可行路线锁在特定同伴或随机装备后面。

三种方法完成相同救援目标，基本任务奖励相同。样板不以“先战斗一次再开关隔离两次”重复领取三份解决奖励；战斗成长的统一处理交给第七、第八部分。

## 12.2 机械状态

| 状态 | 正面进入 | 检修侧道 | 风险区 | 切换规则 |
|---|---|---|---|---|
| `active` 正常威胁 | 确认后进入遭遇 | 尚未安全开放 | 有威胁 | 可去控制器隔离或启动检查 |
| `focused` 保持检查 | 穿过扫描区仍需遭遇确认 | 可安全进入 | 仍有威胁 | 不按时间恢复；可显式取消/隔离 |
| `isolated` 局部隔离 | 可通行 | 可通行 | 不触发 | 不因换场景自动复电 |
| `disabled` 已处置 | 可通行 | 可通行 | 不触发 | 同一遭遇不能被开关重新刷出 |

样板允许在安全点撤销固定检查或解除可恢复的隔离；这种动作不得销毁支架或关闭已打开的回程横闩。任何恢复威胁的动作都须检查角色站位，不能把玩家恢复在必受攻击的区域。正门的风险是双向的：注意固定时仍不能从工坊内部无代价穿越扫描区离开；应走侧道或已打开的横闩门。

`disabled`不能用控制器变回可重复发奖的`active`。不同任务若需要新机械出现，必须有新实例、新事件与明确理由，而不是静默重置。

## 12.3 失败如何返回

战斗失败：返回外场正门的战前安全站位，恢复该检查点战斗资源，保留已经取得的公告、录音、笔记和草稿。

错误设备选择：给出当前设备反馈，允许修改；不消耗船内备用电池，不开启港口主发电机，不制造无法恢复的机器故障。

潜入中选择进入扫描区：先确认将引发遭遇，可取消并回安全路线。没有“玩家读慢了，机械突然转头”的惩罚。

关卡整体复位只用于调试，不作为玩家普通重试方式。正式重试必须声明局部作用范围。

# 13. 样板的信息链、行动链与提交（EXP-13）

## 13.1 推荐游玩链不是强制查看顺序

| 阶段 | 玩家做什么 | 可并行或改变顺序的部分 |
|---|---|---|
| 接受目标 | 在广场/调度室确认撤离任务 | 已有委托不重复考核 |
| 取得信息 | 公告、调度录音、B航道规定、船舶资料与现场检查 | 公告、录音、船舶检查可任意顺序 |
| 取得零件 | 选择三种工坊方法之一 | 可先拿零件再补充路线判断 |
| 修复与验证 | 安装支架、连接备用电池、测试 | 安装与连接可交换；最终测试有实际前置 |
| 表达与确认 | 写撤离指令，核对系统理解到的行动 | 草稿可提前写、随时修改 |
| 执行与后果 | NPC组织撤离，玩家回到广场 | 不把玩家强行送去第二章 |

没有打开足够文献的配额锁；也没有“支架提前拿到就无法交任务”的顺序错误。拥有知识与完成阅读评价并不是同一件事。

## 13.2 不泄漏答案的正常引导

初始任务目标使用“确定并准备可行的撤离方案”，而不是“去西工坊修好灯，然后走C”。地点标记可以指向已知负责方和可调查设施，不提前给出合成结论。

玩家检查装置后，目标可以更新为已观察事实，例如“导航灯支架受损”。这不是系统替代所有材料推理。已经知道支架位置的玩家可以在地图上标注工坊。

语言帮助与解谜帮助仍按CORE-07分开。完整解法由玩家明确请求，不通过普通热点颜色偷偷提供。

## 13.3 写作要求

建议任务提示为一份约90—120词的撤离指令，说明路线、其他路线的限制、导航灯处理和主发电机约束。这个长度是输出负担初值，不是世界动作的硬字数门槛。

正常交互先提供自由文本和现有材料。玩家可以保留草稿离开，也可在广场、调度室和船上继续编辑同一草稿，不能三个入口各生成一份互不相通的正文。

在线服务可辅助理解表达，但不能直接发船；系统展示所理解的行动供确认。离线时通过结构化确认承接世界动作，写作状态保持未评估；显式辅助整理要记录帮助，不标成自主写作。

## 13.4 离港的世界条件

本任务的可执行提交至少满足：

```text
渡轮仍停泊
且 替换支架已经安装
且 船内备用电池已连接且有规定储备
且 导航灯在当前配置下测试通过
且 玩家已确认一份符合航道、设备与主发电机限制的行动方案
且 玩家明确选择执行离港
```

这组条件不读取英语评分、角色加点、字幕设置、提示次数、材料打开数量或联网状态。直接猜到正确路线也不能跳过实体修复与行动确认；同时不能将猜中结果记为已掌握全部技能。

选择B后只启动泵仍然不成立。只认出C却没有安装支架和验证灯，也不能发船。修好设备但尚未说明并确认行动时，船保持停泊，不在玩家写作期间自动出发。

## 13.5 离港后的空间变化

提交时先将玩家及协作角色移动到渡运广场登记的安全站位，再执行NPC撤离的表现与状态改变。这里是明确过渡，不是玩家可以任意穿墙移动。

船体移开，舷梯出口关闭，泊位保留。导航灯、备用电池和已安装支架随该民用渡轮离港，不能再回背包复制。

已经取得的材料继续保留。Q-103若需要新的记录，通过调度室、记录保管间和地区负责人提供，不依赖登上一艘已离港且无法返回的船。

任务结算仅一次。读回离港前存档时可以正常再提交该分支；在离港后的同一世界分支中反复点击回执不再次发奖。

# 14. 重访、状态变体与大量事件（EXP-14）

## 14.1 一张地图不等于一个时间状态

场景表现由少量独立领域组合：设施状态、门/捷径状态、人物可见状态、任务事件、地区结果和环境外观。组合只产生需要的差异，不为所有状态乘积绘制一张新背景。

| 地区变化 | 允许改变 | 必须保留 |
|---|---|---|
| 港口恢复 | 船只位置、工人、公告版本、支线入口 | 原始事故材料、独立工坊状态、已开捷径 |
| 修院供能恢复 | 灯光、温室和住民活动 | 已得名册版本与身份访问范围 |
| 矿区降载 | 运转设备、班次、调度文本 | 安全梯道、已救工人、真实检修记录 |
| 学城试验完成 | 设备模式、后勤门、技术回执 | 失败记录，不得只留成功数据 |
| 旧都接管 | 值守人员、路牌、保管方式 | 已核验责任、救援通路、导师存活 |
| 边境准备完成 | 物资实景、值守和回执 | 各项实际完成状态，不能一键全满 |

用设施状态组合时不能相互矛盾，例如“灯亮”可以来自局部供给，并不自动意味着该塔分布式改造完成。第三部分只改变相应现场表现，不替第十二部分编造未完成的世界事实。

## 14.2 不让重访变成重复劳动

打开的横闩保持打开；已停用的机械不刷新；已救援的人员不被重新放回危险地点；已有文献可看档案。重访必须带来新问题、新视角、人物回应或明确的后续工作，而不是要求玩家再次点击同一排抽屉。

第六章追加的设备安装与试运行是新的实际工作，不是把以前的基础安全任务标成“未完成”。界面要分别标出“当前安全”“本地保全”“增强安装”“试运行”，具体字段由后续统一。

## 14.3 事件插槽

每个合适场景预留事件位置、人物站位、可使用道具和暂时占用范围。事件数据必须声明使用哪些位置与世界状态，不允许AI临时把门口变成新墙。

同一时刻每个场景先限制为一个主导前景事件，另有少量不会抢控制权的环境/生活事件。冲突时主线现场安全与已提交操作优先；支线延后到通信、下一次访问或其他合法站位，而不是悄悄取消。

前景事件不能在玩家打开写作面板时强制切换场景；关键人员不能被低优先级支线挪走造成主线找不到人。装饰人物不阻挡导航，任务NPC的替代沟通位置由设计指定。

可重复练习使用新材料实例与独立评价记录，不复位主线机械，不重新发主线关键装备。

## 14.4 状态冲突处理顺序

事实与玩家已确认的行动优先于装饰。若两个事件争抢同一位置，应由事件调度推迟其一，不能合成一个同时被捕、在船上、在柜台工作的NPC。

门、碰撞、外观和交互可用性需来自同一已提交状态。不能出现美术上门开着、寻路仍堵住，或画面上船已离港但仍可点击舷梯进入。

# 15. 界面在探索中的职责（EXP-15）

## 15.1 玩家始终能取得的位置与任务信息

探索界面提供当前地点、来路、已知出口、当前目标与必要交互提示。地图可将当前选定的调查地点突出显示，但不能把尚未推导的答案写成导航终点。

默认界面不同时堆满背包、词典、技能树、任务列表和大段字幕。调查、材料、写作等打开独立工作区，返回后保留场景位置。详细布局和键位由第十部分统一，本部分只固定行为契约。

## 15.2 可调用的辅助

交互高亮、键盘焦点、出口标签、已得材料、笔记、字幕与译文从当前场景直接调用。不能要求先回微光号升级“字典等级”才查词。

长录音默认可暂停与回放，字幕不依赖播放设备正常工作；有音频缺失时提供对应脚本，并在学习记录中标注实际使用了文本。环境声与装饰声不能覆盖作为任务来源的语音。

## 15.3 主线目标与玩家推理分开

目标栏显示任务目标、已完成的实际动作和已确认事实。证据板保留原文、出处与玩家假设，不能自动替玩家连出全部因果线。

用户主动添加“我打算走C”的笔记，不等于系统已经接受C方案；人物建议走B，也不等于世界规则允许本船走B。只有规则检查与确认行动能够提交任务结果。

## 15.4 长时间返回后的恢复

从存档恢复时显示简短的当前目标、最后已完成行动和未提交草稿入口。材料访问位置和音频进度可恢复。摘要只依据该冒险分支实际记录，不能读取制作文档泄露后续章节。

普通离开菜单、恢复焦点、读取文献，都不自动触发走路、战斗、发送草稿或章节推进。

# 16. 数据语义与跨系统连接（EXP-16）

## 16.1 设计数据至少表达什么

| 数据对象 | 必需含义 | 权限边界 |
|---|---|---|
| 地区定义 | 地区ID、公开名称、入口、场景清单、旅行条件 | 不能自动填满章节任务 |
| 场景定义 | ID、内容版本、用途、故事节点引用、几何、相机、出口、交互物、风险区、事件插槽 | 制作期受控内容 |
| 出口定义 | 源/目标、配对入口、站位、门禁、返程和失败恢复 | 只发起并验证空间迁移 |
| 交互定义 | 动作类别、操作站位、材料/物品/装置引用、前置、提交结果 | 不直接更改学习分数或结局 |
| 场景状态 | 已开门、已拾取、设备模式、处理过的遭遇、变体 | 只存本场景有权拥有的状态 |
| 访问记录 | 已发现/已到访、可用安全点、当前合法通行信息 | 不等于材料理解或全局事实 |
| 学习观察 | 接触哪个材料、采取何种帮助、在什么条件下表达 | 第五部分负责解释，不由地图推断 |

配套JSON提供完整场景/连接登记和六场景几何，但没有完整的任务、学习、战斗和存档接口。将其直接当成正式游戏数据运行之前，需要第四和第十二部分收敛门禁表达与所有权。

## 16.2 唯一所有权

同一事实只有一个权威持有方。场景可以显示任务结果，但不能再私存一个相反的任务完成标记。

| 状态 | 应由谁持有/提交 | 场景如何使用 |
|---|---|---|
| 临时检修委托 | 任务/世界权限 | 检查对应门是否可进入 |
| 支架位置 | 物品与装置事务 | 货架、背包和导航灯显示同一实例的位置 |
| 工坊模式 | 该工坊装置状态 | 影响对应出口与风险区 |
| 船已离港 | 任务世界提交 | 显示船离开、关闭舷梯、保留码头回执 |
| 已听/已看材料 | 内容访问记录 | 提供档案与恢复位置 |
| 英语独立完成证据 | 学习系统 | 仅展示和推荐后续练习，不控制门禁 |
| 第六章准备资格 | 世界准备规则 | 区域地图展示缺项，不根据地图走遍与否计算 |

支架的合法位置只有货架、玩家持有、安装在民用渡轮三个阶段；不能在库存里扣掉了但场景仍可无限拾取。具体物品对象ID与数据库字段留给第十二部分统一。

## 16.3 逻辑接口契约

下面是语义接口，不提前冻结函数名或特定编程语言。

| 请求 | 输入 | 允许返回 | 禁止副作用 |
|---|---|---|---|
| 检查可通行 | 世界分支、场景、出口、当前版本 | 可通行／原因／处理方向 | 不能查一次就自动完成门后的任务 |
| 请求场景迁移 | 配对出口、确认上下文、当前位置 | 到达有效落点／保留原场景 | 不重复扣物或触发两次剧情 |
| 请求现场交互 | 物件ID、动作、选择内容、当前版本 | 可解释结果或受控命令 | 不按自由文本任意执行代码 |
| 请求进入遭遇 | 遭遇ID、玩家明确确认、战前状态 | 进入战斗／取消 | 不因查阅资料自动进入 |
| 接受遭遇结果 | 受控实例、结果、检查点范围 | 开放通路、保留材料、合法结算 | 不重置无关场景与学习历史 |
| 请求旅行 | 出发点、目标、已开放路线、当前任务承诺 | 有效旅行／说明不可折叠的阻碍 | 不跨越进行中的护送或最终阶段 |
| 记录内容交互 | 材料版本、操作、帮助条件 | 访问与学习观察 | 不直接赋予掌握或剧情结果 |

将输入中的场景ID、物件ID和出口ID校验为受控引用。文本建议、NPC对白、模型输出或未知JSON字段不能直接变成世界命令。

## 16.4 版本和过期动作

玩家在写作或查看材料时发生界面切换，旧点击队列必须取消。后台评价返回时只更新相应提交记录，不得在玩家已经离开场景后使用旧确认自动发船。

进入任务绑定材料与规则版本。维护更新若改变门位置或条件，采用明确迁移或保持旧内容，不能让旧存档恢复到新墙体内部，也不能把已安装物品重复生成。

# 17. 存档、失败与场景恢复（EXP-17）

## 17.1 保存边界

门开启、物品转移、设备模式改变、遭遇完成、场景迁移和离港等动作，在稳定边界提交。资源与结果必须一起保存或一起不保存；中间动画可以补播或省略，但不能只保留一半世界结果。

写作草稿、笔记、已经取得的材料与学习接触记录独立保存，不因一场战斗失败消失。具体持久化方案交第十二部分，但本部分的恢复结果必须满足CORE-09。

## 17.2 四种恢复，不得混淆

| 恢复方式 | 恢复哪些状态 | 保留哪些状态 |
|---|---|---|
| 战斗重试 | 本次战前位置、战斗资源和遭遇阶段 | 已得材料、草稿和不属于该战斗的已提交现场动作 |
| 机关局部复位 | 明确列出的设备变量 | 原始文献、永久捷径、已合法拾取物品 |
| 普通存档继续 | 对应冒险分支的完整稳定状态 | 同一玩家的学习接触历史 |
| 读取较早冒险存档 | 世界回到该分支过去状态 | 不伪造第一次见题；不把未来证据塞入过去证据板 |

把一场遭遇的重试写成“重载全章初始场景”不合格。

## 17.3 具体恢复案例

拿到支架后保存，重新进入应显示空货架和一个持有实例。安装后保存，重新进入应显示固定支架、没有可重复拾取的背包副本。

离港提交过程中中断：恢复时要么仍停泊且未发奖，要么已离港并处于广场，不能船已消失但角色仍困在船内。

读回离港前存档：该分支重新完成时应获得应有的单次结算。全局学习档案不能被当成“这个任务曾经发过奖，所以任何回档都不再发奖”的禁止表。

场景变体改变门或物件：已打开的永久通路保持，或提供明确的阶段替代。不得把唯一主线入口交给会因随机生活事件临时走开的NPC。

阅读、调度录音、写作编辑和辅助入口必须是真实可用内容，不能在样板里全部用“以后这里会有英语学习”占位。

## 20.2 本轮实际已经检查什么

配套`Exploration_Validation_v0.1.md`记录实际运行的静态检查。当前结果：78个唯一场景、81条区域内连接、32个主线节点覆盖；六场景有7条内部连接、4个明确标注的演示外边界、36个操作/出口站位；简化工坊侧道在排除扫描区后仍可达支架与回程门。

样板有限状态模型枚举到697个可达状态、2268条动作/移动转换；在声明的规则内，每个可达状态都存在到离港目标的路径。分别只允许战斗、隔离或潜入一种取件方法时，也能完成。配置测试、航道限制和离港位置通过所列抽象回归检查。

这不是完整游戏的可解性证明：模型没有涵盖实际角色半径、引擎碰撞、动态寻路、真实存档、NPC调度、完整战斗资源、输入法、音频与写作服务，也未穷举其余地区的门禁。其余地区的图连通检查是在声明门禁满足后检查连接，不等于任务条件已经验证。

## 20.3 原型试玩的观察指标

首轮继续以少量接近目标能力的玩家找问题，观察是否能辨认来路、出口与目标，是否能发现至少一种非战斗方法，是否将导航地图误当作答案，以及是否能在中断后恢复草稿和任务。

记录“为什么返回”：主动复核、选择另一方案、被迫重复跑图、忘记入口、系统没有保存。不要把所有往返都统计为玩家不熟练，也不要把快速通关当作学习效果证明。

出现关键物品丢失、死路、草稿丢失、声音信息无法访问、错误离港位置、重复奖励或世界/地图状态矛盾时，先修复再扩区。新增场景数量不能抵消这些缺陷。
